# 一个Node的链路

**一轮 = 一个 Node 在其所属 Scenario 下走完，形成明确输入输出；中间的 mode 流转、循环、回退都属于这一轮内部过程。**

下面是完整主链。

## 一、起点：只有原始输入，还没有 Node

系统最开始拿到的是一份原始输入，例如：

* 一个问题
* 一段想法
* 一个任务
* 一段草稿
* 一次用户输入

这时还没有 Node，也谈不上调度、mode、StepRecord。

---

## 二、创建首个 Node

先把原始输入转成系统里的第一个可承载对象。

这一步至少形成：

* `id`
* `title`
* `raw`

这时：

* `summary`
* `conclusion`
* `next`

都允许为空，因为还没经过真正推进。

---

## 三、轻量初始化处理

这一步只做结构准备，不做内容推进。

它负责：

1. 确定 `scenario`
   * 输入倾向明显时，可由 AI 判定
   * 倾向不明显时，由人判定
2. 设置 Node 初始运行状态
   * `status = 未开始`
   * `activeStatus = 启用`
3. 挂入 NodeTree
   * 首个 Node 作为根节点进入树结构
4. 初始化 NodeRuntime
   * `nodeId`
   * `currentMode = null`
   * `isWaitingHuman = false`

到这里为止，这个 Node 才算真正进入系统。

---

## 四、Scheduler 选定当前 Node

现在系统里已经有了一个可运行 Node。
Scheduler 开始工作。

它先做候选过滤，再选当前推进对象。

当前第一轮通常很简单，因为一般只有一个首节点。
以后如果节点多了，Scheduler 再根据：

* `activeStatus`
* `status`
* `next`
* `scenario`
* NodeTree 位置

去做选择。

这一步的结果是：

**当前轮到哪个 Node 进入推进。**

---

## 五、Scheduler 为当前 Node 确定 mode 入口

这一步不是自由乱猜，而是受 scenario 约束。

规则是：

### 1. 如果 `NodeRuntime.currentMode = null`

说明这个 Node 还没真正进入场景工作流。

这时：

* 根据 `scenario`
* 找到该场景的入口 mode

### 2. 如果 `currentMode` 不为空

说明这个 Node 已经在一轮内部推进过。

这时：

* 不重新猜入口
* 直接从当前断面继续

但按我们当前主链推演，第一次通常是 `currentMode = null`。

---

## 六、进入并执行这一轮内部的 mode 流程

这里有一个很重要的边界：

**进入 mode 和执行 mode 合并为同一步。**

也就是说，一旦确定当前 mode，就直接开始这一轮内部推进。
不会再拆成：

* 先记当前位置
* 再单独执行

### 这一轮内部可能发生什么

一个 Scenario 内部可以有多个 mode 流转，例如：

* Explore
* Review
* Revise
* Freeze

这些 mode 可以：

* 线性前进
* 循环
* 回退
* 分支判断

但这些都还属于  **同一个 Node 的同一轮内部过程** 。

---

## 七、这一轮内部运行时，更新什么

这一点我们已经定得比较清楚了：

### 1. 过程中的细粒度变化

只更新：

* `NodeRuntime`
* 原始上下文存储

也就是说，过程中可以不断积累：

* 当前跑到哪个 mode
* 是否等待人工
* 本轮对话过程
* 本轮中间原始输入输出

### 2. 过程中不立即更新什么

这一轮内部过程里，不频繁更新：

* `Node.summary`
* `Node.conclusion`
* `Node.next`
* `StepRecord`

因为这些是 **一轮结束后才统一沉淀** 的东西。

---

## 八、必要时人工介入

如果运行到某一步时，出现这些情况：

* 场景方向不清
* 分支判断无法自动确定
* 是否冻结无法拍板
* 用户意图明显不足

那么系统会进入：

* `NodeRuntime.isWaitingHuman = true`

此时本轮不算完成，只是进入等待人工的中间态。
人工给出选择后，再继续这一轮内部流程。

---

## 九、一轮完成

当这个 Node 在其所属 Scenario 下完成时，这一轮才真正结束。

这里的“完成”不是全系统问题解决了，
而是：

**这个 Node 在这个 Scenario 下，该走的流程走完了，已经形成了本节点这一轮的明确输入输出。**

这时才进入统一沉淀。

---

## 十、生成 StepRecord

一轮结束后，生成一条 StepRecord。

它记录的是这一整轮的沉淀结果，而不是中间每个 mode。

当前最小版本是：

* `id`
* `nodeId`
* `input`
* `output`
* `change`
* `next`

这里的含义是：

* `input`：这一轮的输入
* `output`：这一轮的最终输出
* `change`：这一轮让 Node 发生了什么整体变化
* `next`：这一轮之后，下一步入口是什么

---

## 十一、统一回写 Node

StepRecord 生成后，再统一更新 Node。

主要更新：

* `summary`
* `conclusion`
* `next`
* `status`

这里要注意：

### `status` 怎么变

这一点按你们后续可再细化，但当前可以这样理解：

* 如果这个 Node 这一轮完成后已完全结束，可设为 `已完成`
* 如果这一轮已经形成稳定结果，但仍保留后续重开可能，可设为 `已冻结`

你们后续实现时可以再明确哪种场景进哪个状态。

---

## 十二、必要时创建子节点

如果这一轮的结果带来了新的可推进对象，就在这里创建新的子 Node。

例如：

* 当前节点完成后，拆出几个新的子问题
* 需要切换场景，则不在原 Node 上切换，而是创建新的子节点

然后：

* 新子节点写入 Node
* 关系写入 NodeTree
* 子节点再各自初始化进入系统

这一步非常关键，因为你们已经定了：

**一个 Node 不切换 scenario；若需切换场景，拆成新的子节点。**

---

## 十三、必要时触发 Rescan

如果这一轮完成后带来了上位关键变化，例如：

* `conclusion` 被根本性修正
* 原有冻结结论被推翻
* 后续节点前提发生变化

这时触发 Rescan。

Rescan 只做两件事：

1. 找出受影响节点
2. 让这些节点重新纳入推进流程

它不直接修内容，最后还是交回 Scheduler。

---

## 十四、回到 Scheduler，开始下一轮

当这一轮的：

* StepRecord 已生成
* Node 已回写
* NodeTree 已更新（如有）
* Rescan 已触发（如有）

系统就回到 Scheduler。

然后：

* 从当前启用节点里
* 选择下一个要推进的 Node

进入下一轮。

---

# 压成最短主链

如果只保留主干，就是：

**原始输入 → 创建首个 Node → 轻量初始化 → Scheduler 选当前 Node → 按 scenario 进入并执行本轮 mode 流程 → 过程中更新 NodeRuntime 与原始上下文 → 一轮完成后生成 StepRecord → 统一回写 Node → 必要时创建子节点 / 触发 Rescan → 回到 Scheduler**

---

# 这条链里每个结构的职责

再压一句，防止混：

* **Node** ：承载这个对象当前的内容状态
* **NodeTree** ：承载它与其他节点的关系
* **NodeRuntime** ：承载这一轮内部运行到哪
* **Scheduler** ：决定当前轮到谁
* **StepRecord** ：记录这一轮最终留下了什么
* **Rescan** ：在关键变化后把受影响节点重新送回流程


# 主链阶段清单

## 阶段 1：接收原始输入

目标：系统拿到一份尚未进入框架的原始输入。

输入可能是：

* 一个问题
* 一段想法
* 一份任务描述
* 一段草稿

此时：

* 还没有 Node
* 还没有调度
* 还没有 mode

---

## 阶段 2：创建首个 Node

目标：把原始输入转成系统内可承载的对象。

此阶段至少生成：

* `id`
* `title`
* `raw`

此时允许为空：

* `summary`
* `conclusion`
* `next`

说明：
这一步只是把输入对象化，还不算开始推进。

---

## 阶段 3：轻量初始化处理

目标：让 Node 真正进入系统运行范围。

此阶段完成：

1. 确定 `scenario`
   * 倾向明显：AI 判定
   * 倾向不明显：人工判定
2. 设置 Node 初始状态
   * `status = 未开始`
   * `activeStatus = 启用`
3. 写入 NodeTree
   * 首节点作为根节点挂入树
4. 初始化 NodeRuntime
   * `nodeId`
   * `currentMode = null`
   * `isWaitingHuman = false`

说明：
这一步只做结构准备，不做内容推进。

---

## 阶段 4：Scheduler 选定当前 Node

目标：确定当前轮到哪个 Node 进入推进。

此阶段完成：

* 从启用节点中选出当前推进对象

说明：
首轮通常只有一个 Node，因此选择较简单。
后续多节点时，Scheduler 再按规则筛选和排序。

---

## 阶段 5：确定并进入本轮 mode

目标：让当前 Node 进入其场景工作流中的合适位置。

规则：

1. 若 `NodeRuntime.currentMode = null`
   * 进入该 `scenario` 的入口 mode
2. 若 `currentMode` 不为空
   * 从当前 mode 继续推进

说明：
进入 mode 与执行 mode 合并，不单独拆开。

---

## 阶段 6：执行一轮内部流程

目标：在当前 Node 的 Scenario 内完成本轮推进。

此阶段可能发生：

* mode 前进
* mode 循环
* mode 回退
* 分支判断
* 人工介入

说明：
这些都属于同一个 Node 的同一轮内部过程，
不单独生成 StepRecord。

---

## 阶段 7：运行中更新运行态与原始过程

目标：保存这一轮过程中的运行状态与原始痕迹。

此阶段更新：

* `NodeRuntime`
* 原始上下文存储

此阶段不更新：

* `Node.summary`
* `Node.conclusion`
* `Node.next`
* `StepRecord`

说明：
过程中只保留运行信息和原始过程，不提前沉淀结果。

---

## 阶段 8：必要时人工介入

目标：在系统无法可靠继续时，由人提供关键判断。

触发时机例如：

* 场景倾向不清
* 分支无法自动判断
* 是否冻结无法确定
* 用户隐含目标不足

此阶段表现为：

* `NodeRuntime.isWaitingHuman = true`
* 等待人工输入后再继续本轮流程

说明：
人工介入不代表一轮结束，只是中途等待。

---

## 阶段 9：一轮完成

目标：确认当前 Node 在其所属 Scenario 下，这一轮已经走完。

判定标准：

* 当前 Scenario 在该 Node 上已经形成明确输入输出
* 本轮可以统一沉淀结果
* 本轮不再继续内部 mode 流转

说明：
这里的一轮，是  **Node 级、Scenario 级完成** 。

---

## 阶段 10：生成 StepRecord

目标：记录这一轮最终沉淀下来的结果。

此阶段生成：

* `id`
* `nodeId`
* `input`
* `output`
* `change`
* `next`

说明：
StepRecord 记录的是这一轮完成后的结果，
不是中间每个 mode 的细过程。

---

## 阶段 11：统一回写 Node

目标：把这一轮结果回写到 Node 本体。

此阶段更新：

* `summary`
* `conclusion`
* `next`
* `status`

说明：
Node 的中高密度信息在这里统一更新，
而不是在过程中频繁修改。

---

## 阶段 12：必要时创建子节点

目标：把本轮新产生的可推进对象挂入系统。

触发条件例如：

* 当前节点拆出新的子问题
* 需要切换场景
* 产生新的独立推进对象

此阶段完成：

* 创建新 Node
* 写入 NodeTree
* 后续再走初始化流程

说明：
一个 Node 不切换 scenario。
如果需要切换场景，拆成新的子节点。

---

## 阶段 13：必要时触发 Rescan

目标：当本轮带来关键变化时，让受影响节点重新进入流程。

触发条件例如：

* 核心结论被修正
* 冻结结果被重新打开
* 上位前提变化影响下游节点

此阶段完成：

* 找出受影响节点
* 将其重新纳入推进范围

说明：
Rescan 不直接修内容，只负责重新纳管。

---

## 阶段 14：回到 Scheduler

目标：进入下一轮选择。

此阶段系统重新开始：

* 从启用节点中筛选候选
* 选择下一个当前 Node
* 进入下一轮推进

---

# 最短主链版本

**原始输入 → 创建首个 Node → 轻量初始化 → Scheduler 选当前 Node → 确定并执行本轮 mode 流程 → 过程更新 NodeRuntime 与原始上下文 → 一轮完成 → 生成 StepRecord → 回写 Node → 必要时创建子节点 / 触发 Rescan → 回到 Scheduler**

# 链路分类

Ascend 1.0 的阶段不是全都平级串行的；主干闭环必须走，条件阶段按需插入，运行态更新可并入执行过程。

## 链路跳跃分类

### 1. 首次建 Node 的链路不能跳

当外部新输入第一次进入系统时，

`1 → 2 → 3` 不能跳。

### 2. 一轮推进的闭环不能跳

当某个 Node 真正进入一轮推进时，

`4 → 5 → 6 → 9 → 10 → 11 → 14` 是主干闭环，不建议跳。

### 3. 条件阶段可以不出现

`8 / 12 / 13` 都可以按条件不触发。

`7` 通常并入 `6`，不用单独停下来。

## 链路类型区分

### 首次输入链

1. 接收原始输入
2. 创建 Node
3. 初始化

### 一轮推进主链

4. 选 Node
5. 定 mode
6. 执行内部流程（内含运行态更新）
7. 一轮完成
8. 生成 StepRecord
9. 回写 Node
10. 回到 Scheduler

### 条件插入链

* 必要时人工介入
* 必要时创建子节点
* 必要时触发 Rescan

 **把这条主链压成“明确的阶段清单”** ，也就是分成 1、2、3、4 这样的正式步骤，方便后面直接喂给 AI 去实现。
