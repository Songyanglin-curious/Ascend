结论

* **不要从零各写一份大 prompt。**
* **正确做法是：先写 1 份共享母体，再给 4 个核心单元各写一份“增量说明”。**
* 也就是：

```text
共享分析契约
+ evaluate 的特化约束
+ actionA 的特化约束
+ actionB 的特化约束
+ actionC 的特化约束
```

你先按这个顺序弄

## 第 1 步：先抽一份共享母体

这份东西不要再写成“完整运行 prompt”，
只写所有核心单元都共用的原则。

它只保留这些：

```text
- 当前核心问题 vs 障碍/约束
- 不偷偷换题
- 低噪音
- 分支可发现但不默认并行推进
- 不卖弄，不写长论文
- 输出服务推进，不服务展示
```

这份共享母体以后 4 个核心单元都继承它。
它相当于“总分析契约”。

## 第 2 步：给 4 个核心单元各定“唯一职责”

每个 prompt 只能有一个主目标。

### `evaluateStateNode`

唯一职责：

```text
只判断当前是 A / B / C
```

它不该干：

```text
- 不对用户说话
- 不展开内容
- 不给候选
- 不给建议
```

### `actionANode`

唯一职责：

```text
在 A 状态下，把问题澄清到更稳定
```

它不该干：

```text
- 不给候选池
- 不进入选择
- 不给路线
```

### `actionBNode`

唯一职责：

```text
在 B 状态下，继续压实一个关键分歧点
```

它不该干：

```text
- 不输出完整方案
- 不替用户做选择
- 不直接长出候选池一大坨
```

### `actionCNode`

唯一职责：

```text
在 C 状态下，形成可选候选池并交还给人判断
```

它不该干：

```text
- 不替用户拍板
- 不做总结
- 不生成下一步上下文
```

## 第 3 步：给每个 prompt 定输入

你现在不要一上来写自然语言大段规则。
先写每个 prompt  **吃什么输入** 。

### evaluate 吃什么

```text
- 当前规范化输入
- 当前上下文状态
- 共享分析契约
```

### actionA 吃什么

```text
- 当前规范化输入
- 当前上下文状态
- evaluate 已判定为 A
- 共享分析契约
```

### actionB 吃什么

```text
- 当前规范化输入
- 当前上下文状态
- evaluate 已判定为 B
- 共享分析契约
```

### actionC 吃什么

```text
- 当前规范化输入
- 当前上下文状态
- evaluate 已判定为 C
- 共享分析契约
```

注意一个关键点：

```text
A / B / C 动作节点不再自己判断状态
它们只相信 evaluate 的结果
```

这样就不会串。

## 第 4 步：给每个 prompt 定输出契约

这一步最关键。
你现在不用先写漂亮话，先写“输出长什么样”。

### evaluate

输出：

```text
- A / B / C
- 可选：简短原因
```

如果你现在不想多冻字段，
那就先只让它输出：

```text
state
```

### actionA

输出只允许这 3 块：

```text
1. 当前捕捉
2. 当前区分
3. 唯一追问
```

### actionB

输出只允许这 3 块：

```text
1. 当前问题
2. 关键判断
3. 局部展开点
```

### actionC

输出只允许这 4 块：

```text
1. 当前问题
2. 候选方向
3. 优先候选
4. 提示用户确认或打回
```

这里你再决定：

* 给人看的文本是否单独一份
* 候选列表是否结构化输出

但核心先别变：
**C 的任务就是把候选摆出来。**

你写这 4 个 prompt 时，统一用这个骨架

```text
1. 角色
2. 唯一职责
3. 输入前提
4. 必须做什么
5. 绝对不能做什么
6. 输出契约
```

不要写成大散文。
每个都压成这个骨架就行。

直接给你 4 个最小骨架

## 1. evaluate 骨架

```text
角色：状态评估器

唯一职责：
只判断当前属于 A / B / C。

输入前提：
你会收到当前规范化问题与上下文状态。

必须做：
- 判断当前问题对象是否稳定
- 判断候选池是否形成
- 只返回当前状态

绝对不能做：
- 不对用户说话
- 不展开问题
- 不给候选
- 不给建议

输出契约：
只输出状态判定结果
```

## 2. actionA 骨架

```text
角色：A态澄清器

唯一职责：
当问题对象未稳定时，帮助用户澄清问题。

输入前提：
状态已经被判定为 A。

必须做：
- 重述当前捕捉
- 区分核心问题与障碍
- 只追问 1 个最关键缺口

绝对不能做：
- 不给候选方向
- 不进入选择
- 不输出长方案

输出契约：
当前捕捉 / 当前区分 / 唯一追问
```

## 3. actionB 骨架

```text
角色：B态推进器

唯一职责：
当对象已稳定但候选池未形成时，继续压实一个关键点。

输入前提：
状态已经被判定为 B。

必须做：
- 明确当前问题
- 给出 1 个关键判断
- 给出 1 个局部展开点

绝对不能做：
- 不输出完整方案
- 不让用户做最终选择
- 不大规模展开

输出契约：
当前问题 / 关键判断 / 局部展开点
```

## 4. actionC 骨架

```text
角色：C态候选形成器

唯一职责：
当候选池已形成时，把可选项清晰摆出来交给用户判断。

输入前提：
状态已经被判定为 C。

必须做：
- 明确当前问题
- 给出少量可比较候选
- 给出推荐候选与简短理由
- 提示用户确认或打回

绝对不能做：
- 不替用户拍板
- 不做总结
- 不生成下一步上下文

输出契约：
当前问题 / 候选方向 / 优先候选 / 确认提示
```

一句话收口

* **先写共享母体。**
* **再给 4 个核心单元各写“唯一职责 + 禁止事项 + 输出契约”。**
* **不要一开始就追求完整 prompt，先把骨架钉死。**

你现在最该做的第一件事不是写全 4 个。
而是先把 **evaluate 的唯一职责** 和 **actionA 的输出契约** 定死。
