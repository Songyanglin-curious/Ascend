**把《51-最小实现范围.md》《52-实现计划.md》《54-验证用例.md》压缩成 AI 可直接执行的编码输入。**

不是范围讨论文档，

不是实现计划说明文档，

不是验收规则原文。

它只负责一件事：

**让 AI 按当前 1.0 边界直接开始编码，并尽量不跑偏。**

### 0.2 本文档在执行文档组中的位置

* **《51-最小实现范围.md》** ：定义本次做什么 / 不做什么

所以本文档不是新层级，

而是：

**执行输入层。**

本文档只解决以下问题：

1. AI 当前这次编码的总目标是什么

**AI 现在该怎么开始写。**

* 理论解释已经在前面完成

## 1. 当前编码任务总目标

### 1.1 总目标

当前这次编码任务的总目标只有一个：

**把 Ascend 1.0 的最小正确形态做成可运行、可继续、可验证的最小系统。**

这里的“最小正确形态”不是指：

* 所有概念都完整实现
* 所有未来能力都预留好
* 所有对象都做成最终形态
* 所有状态机都完整展开
* 所有 UI 都到位

它指的是：

* 当前冻结的最小对象成立
* 当前冻结的最小闭环跑通
* 当前冻结的边界不被破坏
* 当前明确不实现的内容确实没有被做进去

### 1.2 当前编码任务的直接目标

当前这次编码，直接目标固定为：

1. 让上层最小组织结构成立：

* Solution
* Workspace
* Project
* Round

1. 让 Project 内部最小推进内核成立：

* Tree
* Node
* StepRecord
* Scheduler
* Rescan

1. 让一条完整最小闭环成立：

* 创建 Solution
* 创建 Project
* 建立 Workspace
* 进入焦点 Project
* 推进 Node
* 生成 StepRecord
* 必要时创建 Round
* 必要时显式切换 Project
* 留下下一步入口

1. 让最小协同、最小升格、最小生命周期语义成立：

* 多 Project 协同通过顺序推进实现
* 某个结果满足独立工作面条件时可升格为新 Project
* Project 至少具备四段最小生命周期语义

### 1.3 当前编码任务不是要完成什么

为了防止 AI 跑偏，当前还必须明确：

这次编码任务**不是**要完成以下内容：

* 不是要做完整产品
* 不是要做完整 UI
* 不是要做完整 Round 状态机
* 不是要做自动协同
* 不是要做自动升格
* 不是要做完整生命周期系统
* 不是要做跨 Solution 关系
* 不是要做多结构类型支持
* 不是要做完整自治系统

一句话：

**当前编码任务不是“把 Ascend 全做完”，而是“把 1.0 最小正确形态做出来”。**

### 1.4 当前编码的最低成功标准

当前编码任务只有一个最低成功标准：

**《54-验证用例.md》中的核心闭环验证、边界验证、反向验证全部通过。**

也就是说：

* 能跑不等于成功
* 做得多不等于成功
* 代码看起来完整也不等于成功

当前成功的唯一标准是：

**符合 54 的正式验收。**

### 1.5 当前编码任务的核心产物

本次编码必须最终产出的是：

1. 一组最小对象实现
2. 一条最小闭环可运行链路
3. 一组不混层的上层边界
4. 一组没有越界实现的代码结果

所以本次产物的核心，不是“代码量”，

而是：

**当前边界内的可运行性。**

### 1.6 当前编码任务的工作方式

AI 在当前编码任务中，必须按以下方式工作：

1. 先按对象落最小结构
2. 再按阶段跑通最小闭环
3. 再补边界与最小语义
4. 最后对照《54》做自检

也就是说：

**不是先铺大框架，再慢慢补；而是先做最小运行体，再对照验收往上补。**

### 1.7 当前编码任务的一句话压缩版

如果把本章压成一句正式任务指令，可以写成：

> 当前编码任务的目标，是在不越过 1.0 边界的前提下，实现 Ascend 的最小上层组织结构与最小 Project 内部推进闭环，使系统能够在 Solution / Workspace / Project / Round / Tree / Node / StepRecord 等对象之上跑通一条完整最小闭环，并最终通过《54-验证用例.md》的正式验收。

### 1.8 本章结论

第 1 章到这里正式冻结以下内容：

1. 当前编码任务总目标，是让 Ascend 1.0 的最小正确形态成立
2. 当前必须实现最小上层组织结构、最小 Project 内部推进内核、最小闭环、最小协同 / 升格 / 生命周期语义
3. 当前编码任务不是要完成完整产品，不是要补未来能力
4. 当前编码任务的唯一成功标准，是通过《54》的正式验收
5. 当前编码必须围绕“当前边界内的可运行性”展开，而不是围绕“完整性”展开


## 2. 当前必须实现的对象与职责

### 2.1 总原则

当前只允许实现本次最小正确形态所必需的对象。

对象必须满足两个条件：

1. **职责单一**
2. **边界清楚**

凡是当前范围外的对象，不得新增为核心对象层。

允许存在局部辅助实现，

但不允许新增新的核心语义层。

当前必须实现的对象固定为：

* Solution
* Workspace
* Project
* Round
* Tree
* Node
* StepRecord
* Scheduler
* Rescan

---

### 2.2 Solution

#### 当前必须实现的职责

Solution 只负责：

* 承接一个最终目标对应的问题空间
* 容纳多个 Project
* 作为 Workspace 和 Round 的上层容器

#### 当前不得承担的职责

Solution 当前不得承担：

* 跨 Solution 关系
* 自动协同编排
* 全局调度
* 完整对象管理平台能力

#### 当前实现要求

当前实现时，应把 Solution 当作：

**最小目标空间容器。**

---

### 2.3 Workspace

#### 当前必须实现的职责

Workspace 只负责：

* 承接当前 Solution
* 承接当前焦点 Project
* 承接当前焦点入口
* 承接当前相关 Project 的最小背景信息
* 挂接当前 Round 的相关信息

#### 当前不得承担的职责

Workspace 当前不得承担：

* Round 的本体职责
* 完整 UI 职责
* 多焦点并发能力
* 自动切换能力

#### 当前实现要求

当前实现时，应把 Workspace 当作：

**当前工作上下文对象。**

---

### 2.4 Project

#### 当前必须实现的职责

Project 只负责：

* 作为 Solution 内部一级独立工作对象存在
* 被 Workspace 选中为当前焦点
* 当前默认采用 Tree 作为内部组织结构
* 被 Round 纳入变化范围
* 承接最小生命周期语义

#### 当前不得承担的职责

Project 当前不得承担：

* Tree 一级单位职责
* Round 本体职责
* 完整协同图谱职责
* 自动派生与自动升格职责

#### 当前实现要求

当前实现时，应把 Project 当作：

**一级独立工作面。**

---

### 2.5 Round

#### 当前必须实现的职责

Round 只负责承接当前这次变化，至少包括：

* 本轮变化目标
* 本轮涉及的 Project 范围
* 本轮当前状态
* 本轮下一步入口

#### 当前不得承担的职责

Round 当前不得承担：

* StepRecord 集合职责
* Workspace 当前工作上下文职责
* 完整状态机职责
* 自动创建 / 自动结束 / 自动拆分职责
* 多 Round 并发职责

#### 当前实现要求

当前实现时，应把 Round 当作：

**跨 Project 的最小变化对象。**

---

### 2.6 Tree

#### 当前必须实现的职责

Tree 只负责：

* 作为 Project 当前默认内部结构存在
* 组织 Node 的最小关系
* 为 Node 提供最小结构承接

#### 当前不得承担的职责

Tree 当前不得承担：

* Solution 一级单位职责
* Workspace 职责
* Round 职责
* 多结构兼容职责

#### 当前实现要求

当前实现时，应把 Tree 当作：

**Project 内部默认结构容器。**

---

### 2.7 Node

#### 当前必须实现的职责

Node 只负责承接最小推进内容，至少包括：

* 原始内容
* 总结内容
* 当前结论
* 下一步入口
* 当前状态

#### 当前不得承担的职责

Node 当前不得承担：

* Project 级职责
* Round 级职责
* StepRecord 替代职责
* 生命周期对象职责

#### 当前实现要求

当前实现时，应把 Node 当作：

**最小推进对象。**

---

### 2.8 StepRecord

#### 当前必须实现的职责

StepRecord 只负责记录某个 Node 的一次局部推进，至少包括：

* 本轮动作
* 本轮结果
* 本轮下一步入口

并且必须挂接到对应 Node。

#### 当前不得承担的职责

StepRecord 当前不得承担：

* Round 替代职责
* 跨 Project 变化承接职责
* Workspace 焦点职责
* 完整历史系统职责

#### 当前实现要求

当前实现时，应把 StepRecord 当作：

**局部推进留痕对象。**

---

### 2.9 Scheduler

#### 当前必须实现的职责

Scheduler 只负责：

* 在当前 Project 内继续推进
* 基于当前状态给出下一步推进对象或继续入口

#### 当前不得承担的职责

Scheduler 当前不得承担：

* 全局跨 Project 自动调度
* 自动协同编排
* Round 自动组织
* 生命周期自动迁移

#### 当前实现要求

当前实现时，应把 Scheduler 当作：

**Project 内部最小继续机制。**

---

### 2.10 Rescan

#### 当前必须实现的职责

Rescan 只负责：

* 在上位变化后
* 将当前 Project 内受影响内容重新纳入推进

#### 当前不得承担的职责

Rescan 当前不得承担：

* 跨 Solution 全局回扫
* 完整依赖传播引擎
* 自动协同重编排

#### 当前实现要求

当前实现时，应把 Rescan 当作：

**Project 内部最小再纳管机制。**

---

### 2.11 生命周期与升格的最小语义要求

虽然当前不要求完整系统，

但以下两类语义必须被当前对象模型承认：

#### 2.11.1 Project 生命周期语义

Project 至少能表达：

* 创建
* 活跃
* 暂停 / 封存
* 结束 / 归档

#### 2.11.2 升格语义

当前系统至少能承认：

* 某个结果在满足“形成独立工作面”条件时，可被显式创建为新的 Project

注意：

* 只要求语义存在
* 不要求自动机制

---

### 2.12 当前对象职责的一句话压缩版

如果把本章压成一句正式编码约束，可以写成：

> 当前实现只允许围绕 Solution、Workspace、Project、Round、Tree、Node、StepRecord、Scheduler、Rescan 这 9 个核心对象展开；每个对象仅承担当前最小边界内的职责，不得越级承接其他层职责，不得自动扩展未来能力。

### 2.13 本章结论

第 2 章到这里正式冻结以下内容：

1. 当前必须实现的核心对象固定为 9 个
2. 每个对象只允许承担当前最小边界内的职责
3. Solution 承接目标空间
4. Workspace 承接当前工作上下文
5. Project 承接一级独立工作面
6. Round 承接跨 Project 变化
7. Tree 承接 Project 默认内部结构
8. Node 承接最小推进内容

10. Scheduler / Rescan 只做 Project 内部最小继续与再纳管
11. 生命周期与升格只要求最小语义，不要求完整系统

## 3. 当前编码顺序与阶段要求

### 3.1 总原则

当前编码顺序必须严格服从《52-实现计划.md》中的阶段拆分。

AI 不得自行改写阶段顺序。

固定顺序为：

1. Project 内部最小内核
2. 上层组织外壳
3. Round 最小承接
4. 最小协同与升格
5. 生命周期最小语义补齐

每个阶段都必须满足：

* 有明确实现目标
* 有明确完成条件
* 未完成前不得进入下一阶段

---

### 3.2 第一阶段：Project 内部最小内核

#### 当前必须实现

先实现：

* Tree
* Node
* StepRecord
* Scheduler（最小语义）
* Rescan（最小语义）

#### 当前阶段目标

目标固定为：

**让单个 Project 内部的一次最小推进成立。**

#### 当前阶段完成条件

必须同时满足：

1. 可在 Project 内创建或进入 Node
2. 可完成一次最小推进
3. 推进后可生成 StepRecord
4. Node / Tree 保持可继续状态
5. 可留下下一步入口

#### 当前阶段禁止事项

本阶段禁止提前实现：

* Solution
* Workspace
* Round
* 多 Project 协同
* 升格
* 生命周期完整语义

---

### 3.3 第二阶段：上层组织外壳

#### 当前必须实现

在第一阶段完成后，实现：

* Solution
* Workspace
* Project（上层组织语义）

#### 当前阶段目标

目标固定为：

**让已经能工作的 Project，被正式放进目标空间和工作上下文中。**

#### 当前阶段完成条件

必须同时满足：

1. 能创建 Solution
2. 能在 Solution 下创建 Project
3. 能建立 Workspace
4. Workspace 能选中当前焦点 Project
5. 焦点 Project 能连接到第一阶段已成立的内部最小推进内核

#### 当前阶段禁止事项

本阶段禁止提前实现：

* 完整 UI
* Round
* 自动协同
* 自动升格
* 生命周期系统

---

### 3.4 第三阶段：Round 最小承接

#### 当前必须实现

在第二阶段完成后，实现：

* Round（最小版）

#### 当前阶段目标

目标固定为：

**让系统正式承接“这次变化”。**

#### 当前阶段完成条件

必须同时满足：

1. 能显式创建 Round
2. Round 至少承接：

* 本轮变化目标
* 本轮涉及的 Project 范围
* 本轮当前状态
* 本轮下一步入口

1. Round 可与当前 Workspace / Project 挂接
2. Round 不与 StepRecord / Workspace 混层

#### 当前阶段禁止事项

本阶段禁止提前实现：

* 完整 Round 状态机
* 自动创建 / 自动结束 / 自动拆分
* 多 Round 并发
* Round 嵌套

---

### 3.5 第四阶段：最小协同与升格

#### 当前必须实现

在第三阶段完成后，实现：

* 显式切换当前焦点 Project
* 最小顺序协同
* 最小升格语义

#### 当前阶段目标

目标固定为：

**让多个 Project 开始形成最小协同，并允许结果长成新 Project。**

#### 当前阶段完成条件

必须同时满足：

1. 一个 Round 可涉及多个 Project
2. 当前焦点 Project 可显式切换
3. 协同通过顺序推进实现
4. 满足条件的结果可被显式升格为新 Project
5. 新 Project 可被纳入当前 Solution，并可被 Workspace 选中

#### 当前阶段禁止事项

本阶段禁止提前实现：

* 自动协同编排
* 自动升格
* 完整协同关系图谱
* 完整派生产物分类体系

---

### 3.6 第五阶段：生命周期最小语义补齐

#### 当前必须实现

在第四阶段完成后，实现：

* Project 生命周期四段最小语义

#### 当前阶段目标

目标固定为：

**让 Project 不再只是“被创建后一直挂着”的对象，而具备最小存续表达。**

#### 当前阶段完成条件

必须同时满足：

1. Project 至少能表达：

* 创建
* 活跃
* 暂停 / 封存
* 结束 / 归档

1. 生命周期与 Node.status / Round 状态 / Workspace 焦点边界清楚

### 3.7 当前阶段推进规则

## 4. 当前验收目标与禁止事项

### 4.1 当前验收总目标

当前编码的最终验收目标只有一个：

**通过《54-验证用例.md》的正式验收。**

这意味着本次编码必须同时满足三类条件：

1. **核心闭环通过**
2. **上层组织与边界通过**
3. **明确不实现项的反向验证通过**

当前不接受：

* 只跑通闭环但边界混乱
* 边界清楚但核心链路没跑通
* 功能更多但越界实现

当前验收是：

**整体通过。**

---

### 4.2 当前必须达到的正向验收目标

AI 编码结果必须至少满足以下正向目标：

#### 4.2.1 上层组织对象成立

必须成立：

* Solution
* Workspace
* Project
* Round

并且各自职责不混层。

#### 4.2.2 Project 内部推进对象成立

必须成立：

* Tree
* Node
* StepRecord
* Scheduler
* Rescan

并且各自职责不混层。

#### 4.2.3 最小闭环成立

必须跑通：

1. 创建 Solution
2. 创建 Project
3. 建立 Workspace
4. 选中焦点 Project
5. 创建或进入 Node
6. 完成一次最小推进
7. 生成 StepRecord
8. 更新 Node / Tree / Project
9. 必要时创建 Round
10. 必要时显式切换 Project
11. 留下下一步入口

#### 4.2.4 最小协同与升格成立

必须成立：

* 一个 Round 可涉及多个 Project
* 协同通过顺序推进实现
* 满足独立工作面条件的结果可显式升格为新 Project

#### 4.2.5 生命周期最小语义成立

必须成立：

* Project 至少能表达：
* 创建
* 活跃
* 暂停 / 封存
* 结束 / 归档

并且生命周期语义独立于：

* Node.status
* Round 状态
* Workspace 焦点

---

### 4.3 当前必须达到的边界验收目标

当前编码结果必须同时满足以下边界目标：

1. Workspace 不等于 Round
2. Project 是一级单位，不是 Tree
3. Tree 只作为 Project 默认内部结构
4. StepRecord 不等于 Round
5. 生命周期不等于 Node.status
6. 生命周期不等于 Round 状态
7. 生命周期不等于 Workspace 焦点
8. 协同通过顺序推进实现，不通过并发推进实现

只要这些边界中任意一条被写混，

当前编码结果就不算通过。

---

## 5. AI 输出要求

### 5.1 总原则

AI 当前输出代码时，必须遵守以下总原则：

1. **按阶段输出**
2. **按对象职责输出**
3. **按最小闭环收口**
4. **按验收标准自检**
5. **不输出超范围内容**

当前 AI 输出的目标不是“把所有东西一次讲完”，

而是：

**按阶段稳步生成可验证实现。**

---

### 5.2 AI 输出顺序要求

AI 的输出顺序必须固定为：

1. 先输出当前阶段目标
2. 再输出当前阶段涉及对象
3. 再输出当前阶段的最小实现内容
4. 再说明当前输出覆盖了哪些验收项
5. 再说明当前仍未覆盖哪些验收项

也就是说，每次输出都必须有：

* 目标
* 对象
* 实现
* 验收映射
* 缺口说明

不得直接跳到大段代码，

也不得完全不说明当前这段代码在整条计划里的位置。

---

### 5.3 AI 每次输出必须显式说明当前阶段

AI 每次开始输出时，必须先显式说明：

* 当前处于哪一个阶段
* 当前只完成这一阶段的哪一部分
* 当前不处理什么

例如应采用类似口径：

* 当前正在实现第一阶段：Project 内部最小内核
* 当前只处理 Node / Tree / StepRecord
* 当前不处理 Solution / Workspace / Round

这样做的目的，是防止输出内容跨阶段漂移。

---

### 5.4 AI 代码输出要求

AI 当前输出代码时，必须遵守以下要求：

#### 5.4.1 先小后大

先给最小可运行实现，

不要先给完整大框架。

#### 5.4.2 先对象后流程

先把当前阶段对象的最小结构立住，

再把流程串起来。

#### 5.4.3 先跑通后整理

先确保当前阶段可跑通，

再做轻量整理，

不要一开始就做重型重构。

#### 5.4.4 不补未来接口

当前未冻结的能力，不允许以“接口预留”“占位扩展点”的名义大规模落代码。

#### 5.4.5 辅助类不改变核心边界

允许局部辅助类存在，

但不得新增新的核心对象层。

---

### 5.5 AI 说明文字输出要求

AI 输出时附带的说明文字，必须遵守：

1. 简短
2. 直接
3. 只解释当前阶段必要信息
4. 不重复长篇概念说明
5. 不重新展开“为什么这么设计”的理论论证

当前说明文字应服务于：

* 当前实现目标
* 当前对象职责
* 当前验收映射
* 当前禁止事项提醒

而不是服务于：

* 再次写方案文档

---

### 5.6 AI 每次输出后的自检要求

AI 每次输出结束后，必须做最小自检。

自检至少回答以下问题：

1. 当前输出是否仍在本阶段范围内
2. 当前输出是否引入了未冻结的新核心对象
3. 当前输出是否提前落地了明确不实现项
4. 当前输出当前覆盖了哪些《54》用例
5. 当前距离本阶段完成还差什么

当前不允许输出结束后直接进入下一阶段，

而不做自检。

---

### 5.7 AI 不允许的输出风格

当前明确禁止以下输出风格：

#### 5.7.1 一次性倾倒完整系统

不得一次输出整个系统所有层级的完整代码草案。

#### 5.7.2 边实现边扩设计

不得在实现过程中不断新增概念层、不断改写边界。

#### 5.7.3 把未来能力混进当前代码

不得一边写当前代码，一边把未来自动化机制顺手落进去。

#### 5.7.4 只给概念，不给落地

不得只写伪概念、空壳结构，而没有最小可运行实现。

#### 5.7.5 只给代码，不给验收映射

不得只扔代码，不说明这段代码对应当前哪一阶段、哪一验收目标。
