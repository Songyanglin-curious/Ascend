
# Ascend 1.0 主链阶段清单

## 阶段 1：接收原始输入

目标：系统拿到一份尚未进入框架的原始输入。

输入可能是：

* 一个问题
* 一段想法
* 一份任务描述
* 一段草稿

此时：

* 还没有 Node
* 还没有调度
* 还没有 mode

---

## 阶段 2：创建首个 Node

目标：把原始输入转成系统内可承载的对象。

此阶段至少生成：

* `id`
* `title`
* `raw`

此时允许为空：

* `summary`
* `conclusion`
* `next`

说明：
这一步只是把输入对象化，还不算开始推进。

---

## 阶段 3：轻量初始化处理

目标：让 Node 真正进入系统运行范围。

此阶段完成：

1. 确定 `scenario`
   * 倾向明显：AI 判定
   * 倾向不明显：人工判定
2. 设置 Node 初始状态
   * `status = 未开始`
   * `activeStatus = 启用`
3. 写入 NodeTree
   * 首节点作为根节点挂入树
4. 初始化 NodeRuntime
   * `nodeId`
   * `currentMode = null`
   * `isWaitingHuman = false`

说明：
这一步只做结构准备，不做内容推进。

---

## 阶段 4：Scheduler 选定当前 Node

目标：确定当前轮到哪个 Node 进入推进。

此阶段完成：

* 从启用节点中选出当前推进对象

说明：
首轮通常只有一个 Node，因此选择较简单。
后续多节点时，Scheduler 再按规则筛选和排序。

---

## 阶段 5：确定并进入本轮 mode

目标：让当前 Node 进入其场景工作流中的合适位置。

规则：

1. 若 `NodeRuntime.currentMode = null`
   * 进入该 `scenario` 的入口 mode
2. 若 `currentMode` 不为空
   * 从当前 mode 继续推进

说明：
进入 mode 与执行 mode 合并，不单独拆开。

---

## 阶段 6：执行一轮内部流程

目标：在当前 Node 的 Scenario 内完成本轮推进。

此阶段可能发生：

* mode 前进
* mode 循环
* mode 回退
* 分支判断
* 人工介入

说明：
这些都属于同一个 Node 的同一轮内部过程，
不单独生成 StepRecord。

---

## 阶段 7：运行中更新运行态与原始过程

目标：保存这一轮过程中的运行状态与原始痕迹。

此阶段更新：

* `NodeRuntime`
* 原始上下文存储

此阶段不更新：

* `Node.summary`
* `Node.conclusion`
* `Node.next`
* `StepRecord`

说明：
过程中只保留运行信息和原始过程，不提前沉淀结果。

---

## 阶段 8：必要时人工介入

目标：在系统无法可靠继续时，由人提供关键判断。

触发时机例如：

* 场景倾向不清
* 分支无法自动判断
* 是否冻结无法确定
* 用户隐含目标不足

此阶段表现为：

* `NodeRuntime.isWaitingHuman = true`
* 等待人工输入后再继续本轮流程

说明：
人工介入不代表一轮结束，只是中途等待。

---

## 阶段 9：一轮完成

目标：确认当前 Node 在其所属 Scenario 下，这一轮已经走完。

判定标准：

* 当前 Scenario 在该 Node 上已经形成明确输入输出
* 本轮可以统一沉淀结果
* 本轮不再继续内部 mode 流转

说明：
这里的一轮，是  **Node 级、Scenario 级完成** 。

---

## 阶段 10：生成 StepRecord

目标：记录这一轮最终沉淀下来的结果。

此阶段生成：

* `id`
* `nodeId`
* `input`
* `output`
* `change`
* `next`

说明：
StepRecord 记录的是这一轮完成后的结果，
不是中间每个 mode 的细过程。

---

## 阶段 11：统一回写 Node

目标：把这一轮结果回写到 Node 本体。

此阶段更新：

* `summary`
* `conclusion`
* `next`
* `status`

说明：
Node 的中高密度信息在这里统一更新，
而不是在过程中频繁修改。

---

## 阶段 12：必要时创建子节点

目标：把本轮新产生的可推进对象挂入系统。

触发条件例如：

* 当前节点拆出新的子问题
* 需要切换场景
* 产生新的独立推进对象

此阶段完成：

* 创建新 Node
* 写入 NodeTree
* 后续再走初始化流程

说明：
一个 Node 不切换 scenario。
如果需要切换场景，拆成新的子节点。

---

## 阶段 13：必要时触发 Rescan

目标：当本轮带来关键变化时，让受影响节点重新进入流程。

触发条件例如：

* 核心结论被修正
* 冻结结果被重新打开
* 上位前提变化影响下游节点

此阶段完成：

* 找出受影响节点
* 将其重新纳入推进范围

说明：
Rescan 不直接修内容，只负责重新纳管。

---

## 阶段 14：回到 Scheduler

目标：进入下一轮选择。

此阶段系统重新开始：

* 从启用节点中筛选候选
* 选择下一个当前 Node
* 进入下一轮推进

---

# 最短主链版本

**原始输入 → 创建首个 Node → 轻量初始化 → Scheduler 选当前 Node → 确定并执行本轮 mode 流程 → 过程更新 NodeRuntime 与原始上下文 → 一轮完成 → 生成 StepRecord → 回写 Node → 必要时创建子节点 / 触发 Rescan → 回到 Scheduler**

# 链路分类

Ascend 1.0 的阶段不是全都平级串行的；主干闭环必须走，条件阶段按需插入，运行态更新可并入执行过程。

## 链路跳跃分类

### 1. 首次建 Node 的链路不能跳

当外部新输入第一次进入系统时，

`1 → 2 → 3` 不能跳。

### 2. 一轮推进的闭环不能跳

当某个 Node 真正进入一轮推进时，

`4 → 5 → 6 → 9 → 10 → 11 → 14` 是主干闭环，不建议跳。

### 3. 条件阶段可以不出现

`8 / 12 / 13` 都可以按条件不触发。

`7` 通常并入 `6`，不用单独停下来。

## 链路类型区分

### 首次输入链

1. 接收原始输入
2. 创建 Node
3. 初始化

### 一轮推进主链

4. 选 Node
5. 定 mode
6. 执行内部流程（内含运行态更新）
7. 一轮完成
8. 生成 StepRecord
9. 回写 Node
10. 回到 Scheduler

### 条件插入链

* 必要时人工介入
* 必要时创建子节点
* 必要时触发 Rescan
