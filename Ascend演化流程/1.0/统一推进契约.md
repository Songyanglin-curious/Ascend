# Ascend 1.0 第一原则：统一推进契约

Ascend 1.0 不以具体任务内容作为统一基础，
而以 **一次最小推进所必须满足的共同结构** 作为统一基础。

无论当前任务是思考、写作、评审、修订还是归档，
只要它要进入 Ascend 1.0，就必须能够被表达为一次推进。

一次推进至少包含五项内容：

## 1. 输入状态

表示当前推进对象在这一轮开始前的状态。

它回答的是：

**现在是在什么基础上继续推进。**

输入状态不要求包含全部历史，
但必须足以支撑当前这一轮继续进行。

## 2. 本轮动作

表示这一轮到底在做什么。

它回答的是：

**这一轮采用什么方式推进。**

本轮动作不等于具体任务内容，
而是对本轮推进性质的抽象表达。
例如探索、写作、评审、修订、冻结等，都属于本轮动作。

## 3. 输出结果

表示这一轮推进后实际产出的内容。

它回答的是：

**这一轮产生了什么新的结果。**

输出结果可以是判断、文本、结构、反馈、修订结果等，
但必须是本轮推进后新增的、可承接的结果。

## 4. 状态变化

表示这一轮之后，推进对象发生了什么变化。

它回答的是：

**这一轮让对象哪里变了。**

状态变化不等于输出结果本身。
输出结果是“产出了什么”，
状态变化是“对象因此变成了什么”。

## 5. 下一步入口

表示这一轮结束后，下一轮最合理的继续点。

它回答的是：

**接下来应从哪里继续推进。**

下一步入口不是完整计划，
而是下一轮最小可继续推进的入口。

---

## 第一原则的含义

Ascend 1.0 的统一性，不来自任务内容相同，
而来自所有任务都必须服从这一推进契约。

也就是说：

* 不同任务可以有不同 Mode
* 不同场景可以有不同组合方式
* 但它们都必须能被表达为：
  * 输入状态
  * 本轮动作
  * 输出结果
  * 状态变化
  * 下一步入口

这五项共同构成 Ascend 1.0 的最小统一骨架。
