因为**“发散—收敛”描述的是某一类任务的内容过程，而“推进契约”描述的是所有任务都必须满足的运行骨架。**

这两者不是一个层级。

前者回答的是：“这一步在干什么。”
后者回答的是：“这一步怎样才算一次有效推进。”

Ascend 真正需要统一的，必须是后者。

一

“发散—收敛”之所以看起来像共性，是因为你最早碰到的强场景，就是那类**对象尚未稳定、需要不断澄清与选择**的任务。

比如：

* 需求还不清
* 问题对象还没钉住
* 候选方向还没形成
* 需要一轮轮探索、筛选、固化

在这种任务里，“发散—收敛”非常贴切。
所以它很容易被误当成整个系统的底层共性。

但问题是，一旦任务类型变了，这个共性就开始失效。

写文章很多时候不是“发散—收敛”，而是“组织—生成—校验”。
评审很多时候不是“发散—收敛”，而是“比对—判断—反馈”。
归档很多时候不是“发散—收敛”，而是“提炼—冻结—承接”。
调度很多时候甚至不处理内容本身，而是在处理“当前该推进什么”。

所以，“发散—收敛”不是错，而是 **只覆盖了一部分模式** 。

二

Ascend 如果把共性定在“发散—收敛”上，会出现一个很直接的问题：

**系统会强迫所有任务都伪装成同一种任务。**

结果就是：

* 写作被硬解释成发散后收敛
* 评审被硬解释成先发散意见再收敛结论
* 调度被硬解释成先发散候选再收敛下一步

这样看似统一了，实际上只是把真实差异抹平了。

这会带来两个后果。

第一个后果，是很多场景会变得别扭。
因为它们的核心矛盾本来就不在“探索对象”，而在别的地方。

第二个后果，是底层骨架会不稳定。
因为你统一的不是“运行方式”，而是“某类任务的内容过程”。一旦内容过程不适用，整个统一性就塌了。

三

所以 Ascend 真正该统一的，不能是“步骤内容”，而必须是 **推进契约** 。

所谓推进契约，就是不管你在做什么，只要这一步被称为一次有效推进，它都应该至少有这几个东西：

* 当前输入状态是什么
* 本轮动作是什么
* 产出了什么结果
* 状态发生了什么变化
* 下一步入口是什么

这五样东西，才是所有任务的真正共性。

因为不管你是：

* Explore
* Select
* Write
* Review
* Revise
* Summarize
* Freeze

本质上都可以描述成：

**一个节点在当前状态下，经过一次推进，产生新的状态、结果和下一步入口。**

这才是 Ascend 能跨场景复用的骨架。

四

这也是为什么“推进契约”比“发散—收敛”更高一层。

“发散—收敛”是模式。
“推进契约”是运行条件。

模式可以有很多种，但运行条件必须统一。

换句话说：

Ascend 不是要规定“所有任务都怎么做”，
而是要规定“所有任务都必须怎样被表示、被记录、被承接”。

这点非常关键。

因为 Ascend 不是只想管思考，还想把：

* 思考
* 写作
* 改写
* 评审
* 归档
* 回扫
* 调度

放进同一套系统里。

要做到这一点，就不能靠某一种内容流程去统一，而只能靠统一契约去承接。

五

从架构上看，这会自然分出三层。

最底层是运行骨架层。
它只定义推进契约，不定义任务内容。
也就是输入、动作、输出、状态、下一步。

中间层是模式层。
这里放 Explore、Write、Review、Freeze 这些不同推进模式。

最上层是场景层。
这里才根据具体任务，把模式组合起来。

于是：

思考场景可以是 Explore → Select → Freeze。
写作场景可以是 Structure → Write → Review → Revise。
需求文档场景可以是 Explore → Select → Structure → Write → Review → Freeze。

这样统一性和扩展性就同时成立了。

六

这也解释了一个很重要的现实问题：

为什么你后来会觉得，Ascend 不能只围绕“思考循环”建。

因为“思考循环”天然带有内容偏向。
它更适合对象不稳定、需要澄清的问题。
但 Ascend 不是只做思考，它要承接的是 **任务推进** 。

任务推进系统的底层单位，不能是“某种思考过程”，而必须是“最小推进单元”。

所以更准确的说法不是：

Ascend 是一个思考框架。

而是：

**Ascend 是一个以推进单元为基础、以推进契约为统一骨架、以模式为可组合能力、以场景为上层编排的任务推进框架。**

七

最后把这件事压成一句话：

**“发散—收敛”统一的是一类任务的内容路径；“推进契约”统一的是所有任务的运行方式。Ascend 要做的是后者，所以它的共性不在“发散—收敛”，而在“推进契约”。**


**共性不在任务内容里，共性在推进单元的契约里。模式负责处理差异，契约负责维持统一。**
