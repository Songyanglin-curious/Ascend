
# 生产管控预警最小页面流程文档

## 1. 目标

当前这份文档只覆盖 **最小闭环流程** ：

**A 建总单并下发给 B → B 创建任务并下发给 C → C 填报并上报 → B 查看/打回 C 或汇总上报 → A 查看/打回 B → B 重提**

不展开：

* 附件流转
* 复杂权限说明
* 页面样式
* 非最小异常分支

---

## 2. 当前对象骨架

先固定当前页面实际围绕的对象：

* **总单** ：`jb_production_main_order`
* **A→B下发** ：`jb_production_main_order_assign`
* **任务** ：`jb_production_task`
* **任务角色** ：`jb_production_task_actor`
* **角色日报** ：`jb_production_task_actor_report`
* **B当日上报** ：`jb_production_b_daily_submission`
* **B上报关联明细** ：`jb_production_b_daily_submission_actor_report_rel`

---

## 3. 页面最小流程总览

### A侧

1. 创建总单
2. 向 B 下发总单

### B侧

1. 查看 A 下发给自己的待处理总单
2. 基于总单创建任务
3. 给任务挂角色人
   * 工作负责人
   * 到岗到位
4. 把 A→B 下发标记为已处理
5. 按日期查看 C 的角色日报状态
6. 打回 C 的角色日报
7. 发起当日上报
8. 查看自己今天的上报及其明细
9. 被 A 打回后重提

### C侧

1. 查看自己今日待办
2. 按日期查看自己的任务
3. 查看某个任务角色在某日的详情
4. 首次创建今日日报
5. 保存/完成/提交今日日报
6. 被 B 打回后继续修改并重新提交

### A侧

1. 按日期查看 B 上报列表
2. 打回 B 上报

### 5.3 B 基于总单创建任务并挂角色

这是 B 侧最关键的创建动作。

创建任务并挂载到两个角色上，将A下发B任务的状态改为已处理。

```js
fetch('http://10.15.0.77:7032/api/PDP', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    args: [
      {
        type: "new",
        db: "JB",
        sql: "jb/production_alert:CreateTask",
        args: [
          11,                          // 总单ID main_order_id
          "大风天气线路特巡任务",            // 任务名称
          "2026-03-14 09:30:00",           // 开始时间
          "2026-03-20 18:00:00",           // 结束时间
          "b_user_001",                  // 当前B用户ID created_by
           "张三",
          "张家口变电站",                    // 变电站名称
          "线路运维一班"                     // 班组名称
        
        ]
      },
      {
        type: "new",
        db: "JB",
        sql: "jb/production_alert:CreateTaskActorWorkOwner",
        args: [
          { ref: "0", value: -1, type: "string" }, // 上一步返回的 task_id
          "c_user_001",                            // 工作负责人C ID
          "王五",                               // 工作负责人C用户名
          "b_user_001"                           // 当前B用户ID
        ]
      },
      {
        type: "new",
        db: "JB",
        sql: "jb/production_alert:CreateTaskActorOnDutyCheck",
        args: [
          { ref: "0", value: -1, type: "string" }, // 上一步返回的 task_id
          "c_user_002",                            // 到岗到位C ID
          "赵六",                              // 到岗到位C用户名
          "b_user_001"                           // 当前B用户ID
        ]
      },
      {
        type: "modify",
        db: "JB",
        sql: "jb/production_alert:MarkMainOrderAssignProcessedByB",
        args: [
          17,             // A→B 下发记录 assign_id

        ]

    ]
  })

.then(response => response.json())

  console.log('Success:', data);
```

**页面动作**

**页面动作**

#### 5.3.4 把 A→B 下发标记为已处理

**页面动作**

* 任务和角色都创建完成后，将原 A→B 下发记录置为已处理

**调用元接口**

* `MarkMainOrderAssignProcessedByB`

**调用顺序**
推荐放在下面三步之后：

1. `CreateTask`
2. `CreateTaskActorWorkOwner`（如果有）
3. `CreateTaskActorOnDutyCheck`（如果有）
4. `MarkMainOrderAssignProcessedByB`

**建议**

* 这四步最好由页面组合成一个“完成下发”动作
* 实际服务层最好包事务

### 5.7 B 发起今日上报

这是 B 上报的最小闭环。

**页面动作**

* B 点“今日上报”
* 系统自动收今天全部可报角色日报，不做手动勾选

**调用元接口**

* `GetBDailySubmissionForBUserToday`
* `CreateBDailySubmissionForToday`
* `AttachTodaySubmittableTaskActorReportsToBDailySubmission`

**调用顺序**
推荐这样：

#### 情况 A：今天还没有 submission

1. 先调 `GetBDailySubmissionForBUserToday`
2. 若不存在，则调 `CreateBDailySubmissionForToday`
3. 再调 `AttachTodaySubmittableTaskActorReportsToBDailySubmission`

```js
fetch('http://10.15.0.77:7032/api/PDP', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    args: [

      {
        type: "new",
        db: "JB",
        sql: "jb/production_alert:CreateBDailySubmissionForToday",
        args: [
          "b_user_001",
          "今日生产管控日报上报"
        ]
      },
      {
        type: "new",
        db: "JB",
        sql: "jb/production_alert:AttachTodaySubmittableTaskActorReportsToBDailySubmission",
        args: [
          { ref: "0", value: -1, type: "string" },
          "b_user_001"
        ]
      }
    ]
  })
})
.then(response => response.json())
.then(data => {
  console.log('Success:', data);
})
.catch(error => {
  console.error('Error:', error);
});
```

#### 情况 B：今天已经有 submission

1. 调 `GetBDailySubmissionForBUserToday`
2. 若已存在，原则上不再新建
3. 当前最小实现下，通常这一天不重复发起新的上报

**备注**

* 你们当前骨架是一日一条 B 上报实例
* 不做手动勾选

### 5.10 B 被 A 打回后重新提交

这是 B 重提链路。

**页面动作**

* B 打开被 A 打回的 submission
* 点击“重新提交”
* 系统先清旧关联，再重新自动收今日可报日报，再重提

**调用元接口**

* `DeleteTaskActorReportsByBDailySubmission`
* `InsertTodaySubmittableActorReportsToRejectedBDailySubmission`
* `ResubmitBDailySubmission`

**调用顺序**

1. 调 `DeleteTaskActorReportsByBDailySubmission`
2. 调 `InsertTodaySubmittableActorReportsToRejectedBDailySubmission`
3. 校验新插入的关联明细数是否大于 0
4. 调 `ResubmitBDailySubmission`

**强建议**

* 这三步应由页面组合成一个“重提”动作
* 服务层应放在**一个事务**里

```js
fetch('http://10.15.0.77:7032/api/PDP', {
```

## 10. 当前最需要注意的实现边界

### 第一

**B 上报是自动收当天全部 `SUBMITTED` 的角色日报**
不是手动勾选

### 第二

**A 打回 B 时不清关联**
清旧 rel 发生在 **B 重提前**

### 第三

**C 被打回后继续改原日报**
不是新建新日报

### 第四

**B 重提链路必须做事务**
否则容易删了旧 rel 但没成功重建
