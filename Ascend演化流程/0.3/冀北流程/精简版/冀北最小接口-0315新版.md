# 生产管控预警前端最小接口文档（新版）

## 1. 文档目的

本文档用于定义当前版本前端最小闭环所需的最小接口集、最小页面组织方式以及最小调用顺序。

本文档采用当前 XML 的实现口径，不再沿用旧的“B 当日唯一上报”表述。

当前统一口径如下：

- A 创建总单并下发给 B。
- B 基于总单创建任务，并为任务配置 C 角色。
- C 围绕任务角色按日填报日报。
- B 查看并处理 C 上报。
- B 以“某总单、某日”为单位向 A 发起上送。
- A 以“某总单、某日”为单位查看并打回 B 上送。
- B 在原上送实例上重提。

本文档面向前端与后端联调，不面向外部说明。

## 2. 调用约定

### 2.1 请求地址

统一调用：

```javascript
fetch('http://10.15.0.77:7032/api/PDP', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    args: [
      // 每个对象为一次元接口调用
    ]
  })
})
.then(response => response.json())
.then(data => {
  console.log('Success:', data);
})
.catch(error => {
  console.error('Error:', error);
});
```

### 2.2 元接口类型

- `load`：读取，参数以对象形式传入，字段使用 `xml`
- `read`：读取，参数以数组形式传入，字段使用 `sql`
- `modify`：更新，字段使用 `sql`
- `new`：新增，字段使用 `sql`，通常返回自增主键

### 2.3 引用本次新增返回的自增 ID

```javascript
{ ref: "0", value: -1, type: "string" }
```

表示引用本次 `args` 数组中第 `0` 个调用返回的自增 ID。

## 3. 当前最小对象

前端需理解以下最小对象：

- 总单：`jb_production_main_order`
- A→B 下发关系：`jb_production_main_order_assign`
- 任务：`jb_production_task`
- 任务角色：`jb_production_task_actor`
- 任务角色日报：`jb_production_task_actor_report`
- B 上送实例：`jb_production_b_daily_submission`
- B 上送与日报关联：`jb_production_b_daily_submission_actor_report_rel`

其中，当前 B 上送实例的实现口径应理解为：

**某 B、某总单、某日的一份上送实例。**

因此前端不应再将 submission 理解为“B 当日唯一一份上送”。

## 4. 页面最小菜单建议

### 4.1 A 侧

- 创建总单
- 下发给 B
- 活跃总单列表
- 某总单当日 B 上报列表
- 打回 B 上报

### 4.2 B 侧

- 待处理总单
- 全部总单
- 创建任务 / 配置角色
- C 上报列表
- 打回 C 上报
- 某总单今日可上报列表
- 某总单今日上报记录

### 4.3 C 侧

- 今日待办
- 我的任务
- 任务详情 / 填报
- 提交日报

## 5.10 B：发起某总单今日上报

当前 submission 的最小口径为：

**某 B、某总单、某日的一份上送实例。**

## 7. 关键规则

### 7.1 C 填报规则

- C 按任务角色填报日报。
- 同一任务角色、同一日期只允许一条日报实例。
- 已提交日报仅可由 B 打回后再修改。

### 7.2 B 查看规则

- B 的 C 上报列表是内部回收与审核列表。
- B 的对 A 上送列表必须按总单隔离。

### 7.3 B→A 上送规则

- B 对 A 的 submission 不得跨总单混合。
- B 在同一日期下，可针对不同总单分别形成不同 submission。
- B 当前最小上送口径为：某 B、某总单、某日一份 submission。

### 7.4 A 查看规则

- A 应先看活跃总单，再进入某总单查看 B 上报。
- A 打回的对象是某总单、某日的一份 submission，而不是 B 当日全部内容。

## 8. 当前不再采用的旧口径

以下旧口径不再作为当前最小实现口径：

- “B 当日唯一 submission”
- “B 今日全部可上送池统一挂接”
- “A 按日期直接查看全部 B submission 且不区分总单”

如果旧接口仍暂时存在，也仅视为兼容遗留，不应作为前端新接入入口。

## 9. 一句冻结结论

当前最小接口体系应统一理解为：

**A 按总单下发，B 按总单创建任务，C 按任务角色填报，B 按总单按日聚合上送，A 按总单按日查看与打回。**
