# 表结构字段说明清单

## 1. `jb_production_b_daily_submission`

中文名：**B 当日上送表**

表定位：记录 B 某一天向 A 发起的一次整份上送实例。一个 B 一天只保留一份上送实例；A 打回的是整份 submission，不是其中某条日报。日报集合必须通过关联表显式保存。

| 字段名              | 类型            | 是否必填 | 字段说明                   | 填写方   | 何时写入/变化             | 备注                                          |
| ------------------- | --------------- | -------: | -------------------------- | -------- | ------------------------- | --------------------------------------------- |
| `id`              | bigint unsigned |       是 | 主键 ID                    | 系统     | 插入时生成                | 自增主键                                      |
| `b_user_id`       | varchar(50)     |       是 | 该上送实例所属 B 用户 ID   | B / 系统 | 创建 submission 时写入    | 与 `submission_date`组成单日唯一            |
| `submission_date` | date            |       是 | 这份上送归属的业务日期     | 系统 / B | 创建 submission 时写入    | 表示“哪一天的上送”，不是更新时间            |
| `remark`          | text            |       否 | B 对本次整份上送的备注说明 | B        | 创建或重提时可写          | 备注不是重新生产核心业务内容，只是补充说明    |
| `state`           | varchar(20)     |       是 | 上送实例状态               | 系统     | 创建/提交/打回/重提时变化 | 当前 DDL 注释：`CREATED/SUBMITTED/REJECTED` |
| `submitted_at`    | datetime        |       否 | 正式提交给 A 的时间        | 系统     | 首次提交、重提时写入/覆盖 | 建议重提时刷新为最新提交时间                  |
| `rejected_reason` | varchar(500)    |       否 | A 打回原因                 | A        | A 打回时写入              | 只有 A 打回 B 时才会填                        |
| `updated_at`      | datetime        |       是 | 最后更新时间               | 系统     | 每次更新自动变化          | `on update CURRENT_TIMESTAMP`               |

### 状态说明

| 状态值        | 含义                 | 谁触发   |
| ------------- | -------------------- | -------- |
| `CREATED`   | 已创建但还未正式提交 | B / 系统 |
| `SUBMITTED` | 已正式上送给 A       | B / 系统 |
| `REJECTED`  | 被 A 打回            | A        |

### 关键约束

| 约束                                    | 含义                              |
| --------------------------------------- | --------------------------------- |
| `unique (b_user_id, submission_date)` | 一个 B 在某一天只保留一份上送实例 |

### 实现备注

* B 发起上送时，系统自动纳入当天 **已提交且未被打回** 的有效日报，不做手工勾选。
* A 打回后，不应新建第二份 submission；应在原 submission 上重提。

## 2. `jb_production_b_daily_submission_actor_report_rel`

中文名：**B 上送与任务角色日报关联表**

表定位：显式记录“某次 B 上送，实际带了哪些角色日报”。这张表不能省，A 查详情、缺口计算、追溯都依赖它。

| 字段名                   | 类型            | 是否必填 | 字段说明                    | 填写方 | 何时写入/变化     | 备注                                         |
| ------------------------ | --------------- | -------: | --------------------------- | ------ | ----------------- | -------------------------------------------- |
| `id`                   | bigint unsigned |       是 | 主键 ID                     | 系统   | 插入时生成        | 自增主键                                     |
| `submission_id`        | bigint unsigned |       是 | 所属 B 上送实例 ID          | 系统   | B 提交/重提时插入 | 指向 `jb_production_b_daily_submission.id` |
| `task_actor_report_id` | bigint unsigned |       是 | 被纳入本次上送的角色日报 ID | 系统   | B 提交/重提时插入 | 指向 `jb_production_task_actor_report.id`  |

### 关键约束

| 约束                                             | 含义                                   |
| ------------------------------------------------ | -------------------------------------- |
| `unique (submission_id, task_actor_report_id)` | 同一份上送中，同一条日报只允许关联一次 |

### 实现备注

* 这张表只记录“当次实际上送的集合”，不能靠事后按条件临时推断。
* B 重提时，应先清旧关联，再重挂今日新的可上送日报，最后将 submission 重新置为 `SUBMITTED`。这条链路应事务化。

## 3. `jb_production_main_order`

中文名：**总单表**

表定位：A 发起的顶层安排对象，是后续任务的来源。总单当前不承担复杂审批流和复杂状态。

| 字段名                | 类型            | 是否必填 | 字段说明       | 填写方   | 何时写入/变化 | 备注                     |
| --------------------- | --------------- | -------: | -------------- | -------- | ------------- | ------------------------ |
| `id`                | bigint unsigned |       是 | 主键 ID        | 系统     | 插入时生成    | 自增主键                 |
| `title`             | varchar(200)    |       是 | 总单标题       | A        | 创建时写入    | 核心展示字段             |
| `notice_no`         | varchar(100)    |       否 | 通知编号       | A        | 创建时写入    | 如“灾害预警2024第01号” |
| `publish_time`      | datetime        |       否 | 发布时间       | A        | 创建时写入    | 顶层通知的发布时间       |
| `hazard_category`   | varchar(50)     |       否 | 险情类别       | A        | 创建时写入    | 如大风、暴雪等           |
| `warning_level`     | varchar(50)     |       否 | 预警级别       | A        | 创建时写入    | 如蓝色预警               |
| `impact_start_time` | datetime        |       否 | 影响开始时间   | A        | 创建时写入    | 业务影响区间开始         |
| `impact_end_time`   | datetime        |       否 | 影响结束时间   | A        | 创建时写入    | 业务影响区间结束         |
| `event_summary`     | longtext        |       否 | 事件概要       | A        | 创建时写入    | 面向业务描述             |
| `content`           | text            |       否 | 总单内容说明   | A        | 创建时写入    | 可用于详细说明           |
| `created_by`        | varchar(50)     |       是 | 创建人 ID（A） | A / 系统 | 创建时写入    | 当前总单责任来源         |
| `created_at`        | datetime        |       是 | 创建时间       | 系统     | 插入时写入    | 默认当前时间             |

### 实现备注

* 当前表里没有 `state`，这是可以成立的：总单在 V1 只是顶层来源对象，不需要复杂流程状态。
* 一条总单可以下发给多个 B，也可以被多个 B 派生出多条任务。

## 4. `jb_production_main_order_assign`

中文名：**总单下发 B 关系表**

表定位：记录 A 把某个总单下发给哪些 B。你当前实现已经把这层承接关系显式拆出来了，和最早“最小 5 表”相比，这是实现层细化。当前页面流程里，B 会查看待处理总单，并在建任务完成后把这条关系置为已处理。

| 字段名                   | 类型            | 是否必填 | 字段说明               | 填写方   | 何时写入/变化                                          | 备注                                 |
| ------------------------ | --------------- | -------: | ---------------------- | -------- | ------------------------------------------------------ | ------------------------------------ |
| `id`                   | bigint unsigned |       是 | 主键 ID                | 系统     | 插入时生成                                             | 自增主键                             |
| `main_order_id`        | bigint unsigned |       是 | 所属总单 ID            | 系统 / A | A 下发给 B 时写入                                      | 指向 `jb_production_main_order.id` |
| `receiver_b_id`        | varchar(50)     |       是 | 接收该总单的 B 用户 ID | A        | 下发时写入                                             | 一个总单可发给多个 B                 |
| `receiver_b_name`      | varchar(50)     |       否 | B 姓名快照             | A / 系统 | 下发时写入                                             | 冗余快照，便于展示                   |
| `receiver_b_dept_name` | varchar(100)    |       否 | B 部门名称快照         | A / 系统 | 下发时写入                                             | 冗余快照，便于展示                   |
| `assigned_by`          | varchar(50)     |       是 | 下发人 ID（A）         | A / 系统 | 下发时写入                                             | 表示谁做了下发动作                   |
| `assigned_at`          | datetime        |       是 | 下发时间               | 系统     | 插入时写入                                             | 默认当前时间                         |
| `status`               | varchar(30)     |       否 | 下发处理状态           | 系统 / B | 创建时默认 `pending`，B 建任务完成后改 `processed` | 当前 DDL 注释：`pending/processed` |

### 状态说明

| 状态值        | 含义                            | 谁触发   |
| ------------- | ------------------------------- | -------- |
| `pending`   | A 已下发，B 尚未完成承接处理    | A / 系统 |
| `processed` | B 已基于此下发完成任务创建/承接 | B / 系统 |

### 关键约束

| 约束                                      | 含义                           |
| ----------------------------------------- | ------------------------------ |
| `unique (main_order_id, receiver_b_id)` | 同一总单不会重复下发给同一个 B |

### 实现备注

* 这张表主要服务 B 的“待处理总单 / 全部总单”视图。
* 当前推荐口径是：B 把任务和角色创建完成后，再把这条 `assign` 置为 `processed`。

## 5. `jb_production_task`

中文名：**任务表**

表定位：B 基于总单创建的主业务对象。任务是跨天对象，是后续“应报范围”的计算基础；主链围绕任务走，不围绕人走。

| 字段名              | 类型            | 是否必填 | 字段说明         | 填写方   | 何时写入/变化  | 备注                                 |
| ------------------- | --------------- | -------: | ---------------- | -------- | -------------- | ------------------------------------ |
| `id`              | bigint unsigned |       是 | 主键 ID          | 系统     | 插入时生成     | 自增主键                             |
| `main_order_id`   | bigint unsigned |       是 | 所属总单 ID      | B / 系统 | 创建任务时写入 | 指向 `jb_production_main_order.id` |
| `station_name`    | varchar(100)    |       否 | 变电站名称快照   | B        | 创建时写入     | 展示和统计辅助字段                   |
| `team_name`       | varchar(100)    |       否 | 班组名称快照     | B        | 创建时写入     | 展示和统计辅助字段                   |
| `task_name`       | varchar(200)    |       是 | 任务名称         | B        | 创建时写入     | 任务主标题                           |
| `start_time`      | datetime        |       是 | 任务开始时间     | B        | 创建时写入     | 用于计算是否应报                     |
| `end_time`        | datetime        |       是 | 任务结束时间     | B        | 创建时写入     | 用于计算是否应报                     |
| `created_by`      | varchar(50)     |       是 | 创建人 ID（B）   | B / 系统 | 创建时写入     | 谁建的任务                           |
| `created_at`      | datetime        |       是 | 创建时间         | 系统     | 插入时写入     | 默认当前时间                         |
| `created_by_name` | varchar(50)     |       否 | B 创建人姓名快照 | B / 系统 | 创建时写入     | 冗余快照                             |

### 实现备注

* 当前表没有 `status` 字段，但这在 V1 可以接受；任务“进行中/已结束”可由 `start_time`、`end_time` 与查询日期推导。
* 当前真实实现已经把“责任人”从任务表中拆到了 `task_actor`，说明任务仍是主轴，责任人是挂在任务下的角色属性。

## 6. `jb_production_task_actor`

中文名：**任务角色表**

表定位：记录某个任务下有哪些角色，由哪些 C 承担。当前页面流程明确存在“工作负责人”“到岗到位”等角色。

| 字段名          | 类型            | 是否必填 | 字段说明               | 填写方   | 何时写入/变化 | 备注                                          |
| --------------- | --------------- | -------: | ---------------------- | -------- | ------------- | --------------------------------------------- |
| `id`          | bigint unsigned |       是 | 主键 ID                | 系统     | 插入时生成    | 自增主键                                      |
| `task_id`     | bigint unsigned |       是 | 所属任务 ID            | B / 系统 | 挂角色时写入  | 指向 `jb_production_task.id`                |
| `actor_type`  | varchar(50)     |       是 | 角色类型               | B        | 挂角色时写入  | 当前 DDL 注释：`WORK_OWNER / ON_DUTY_CHECK` |
| `c_user_id`   | varchar(50)     |       是 | 该角色对应的 C 用户 ID | B        | 挂角色时写入  | 谁承担这个角色                                |
| `created_by`  | varchar(50)     |       是 | 创建人（B）            | B / 系统 | 创建时写入    | 谁配置了角色                                  |
| `created_at`  | datetime        |       是 | 创建时间               | 系统     | 插入时写入    | 默认当前时间                                  |
| `c_user_name` | varchar(50)     |       否 | C 用户名快照           | B / 系统 | 创建时写入    | 冗余快照                                      |

### 关键约束

| 约束                             | 含义                                   |
| -------------------------------- | -------------------------------------- |
| `unique (task_id, actor_type)` | 同一任务下，同一角色类型只允许配置一次 |

### 实现备注

* 这一版实现默认：一个任务下每种角色类型只挂一个 C。是否支持“一任务多人”明确不在 V1 范围内。
* 任务角色是日报填报的直接归属对象，后面的日报唯一约束是按 `task_actor_id + report_date` 形成的。

## 7. `jb_production_task_actor_report`

中文名：**任务角色日报表**

表定位：C 围绕某个任务角色、某一天提交的一条日报实例。日报是单日单实例；提交后锁定；被 B 打回后在原记录上修改重提，不新建并列记录。

| 字段名                      | 类型            | 是否必填 | 字段说明         | 填写方   | 何时写入/变化                  | 备注                                                                                                                              |
| --------------------------- | --------------- | -------: | ---------------- | -------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `id`                      | bigint unsigned |       是 | 主键 ID          | 系统     | 插入时生成                     | 自增主键                                                                                                                          |
| `task_id`                 | bigint unsigned |       是 | 所属任务 ID      | 系统 / C | 首次建日报时写入               | 指向 `jb_production_task.id`                                                                                                    |
| `task_actor_id`           | varchar(50)     |       是 | 所属任务角色 ID  | 系统 / C | 首次建日报时写入               | 逻辑上应指向 `jb_production_task_actor.id`；当前 DDL 类型写成了 `varchar(50)`，与上游 `bigint unsigned`不一致，建议后续统一 |
| `report_date`             | date            |       是 | 日报所属业务日期 | 系统 / C | 首次建日报时写入               | 用于形成单日唯一                                                                                                                  |
| `patrol_person_count`     | int unsigned    |       否 | 巡视人员数       | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `vehicle_count`           | int unsigned    |       否 | 车辆数           | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `patrol_line_count`       | int unsigned    |       否 | 巡视线路数       | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `patrol_km`               | decimal(10,2)   |       否 | 巡视公里数       | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `substation_count`        | int unsigned    |       否 | 变电站数         | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `converter_station_count` | int unsigned    |       否 | 换流站数         | C        | 填报/修改时写入                | 业务数值字段                                                                                                                      |
| `remark`                  | text            |       否 | 日报备注         | C        | 填报/修改时写入                | 文本补充说明                                                                                                                      |
| `state`                   | varchar(20)     |       是 | 日报状态         | 系统     | 创建/保存/提交/打回/重提时变化 | 当前 DDL 注释：`CREATED/DONE/SUBMITTED/REJECTED`                                                                                |
| `submitted_at`            | datetime        |       否 | 正式提交时间     | 系统     | C 提交、重提时写入/覆盖        | 提交后锁定                                                                                                                        |
| `rejected_reason`         | varchar(500)    |       否 | B 打回原因       | B        | B 打回时写入                   | 仅 B 可写                                                                                                                         |
| `updated_at`              | datetime        |       是 | 最后更新时间     | 系统     | 每次更新自动变化               | `on update CURRENT_TIMESTAMP`                                                                                                   |

### 状态说明

| 状态值        | 含义                   | 谁触发   |
| ------------- | ---------------------- | -------- |
| `CREATED`   | 草稿初始态             | C / 系统 |
| `DONE`      | 已完成填写但未正式提交 | C        |
| `SUBMITTED` | 已正式提交给 B         | C / 系统 |
| `REJECTED`  | 被 B 打回              | B        |

### 关键约束

| 约束                                    | 含义                             |
| --------------------------------------- | -------------------------------- |
| `unique (task_actor_id, report_date)` | 同一任务角色同一天只能有一条日报 |

### 实现备注

* 业务口径可以说“未报 / 已提交 / 被打回”，但真实实现已经扩成四态：`CREATED / DONE / SUBMITTED / REJECTED`。
* “未报”通常不是存一条状态，而是  **应报范围内没有对应日报记录** 。
* B 对日报没有“逐条通过”，只有打回；正常项默认成立。

## 10. 当前最值得在文档里单独标红的点

| 点               | 说明                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 日报唯一口径     | 当前实现是**`task_actor_id + report_date`唯一** ，不是 `task_id + report_date`唯一                                    |
| B 单日上送唯一   | 当前实现是**`b_user_id + submission_date`唯一**                                                                               |
| 上送集合必须落表 | 不能靠临时查询反推，必须保留 rel                                                                                                |
| 打回分层         | A 打回 B 的 submission；B 打回 C 的日报；不越级改                                                                               |
| 自动纳入         | B 上送自动收当天有效 `SUBMITTED`日报，不做手工勾选                                                                            |
| 一个潜在结构问题 | `task_actor_report.task_actor_id`目前是 `varchar(50)`，而 `task_actor.id`是 `bigint unsigned`，类型不一致，后面建议统一 |
