
# 冀北流程 V1 技术骨架说明

## 1. 文档目的

**让技术人员对这条流程的主线、主对象、主规则形成一致认识。**

V1 当前只追求主流程闭环跑通，不处理复杂边界。主线是：

**A 建总单并下发给 B → B 基于总单建任务并下发给 C → C 按天填报并提交 → B 查看、必要时打回 → B 按天向 A 上送 → A 查看、必要时打回 → B 在原上送实例上重提。**

## 2. 角色分工

### A：生产管控层

职责是：

* 创建总单
* 将总单下发给多个 B
* 查看各 B 的当日上送结果
* 必要时打回 B 的整份上送

### B：分部层

职责是：

* 承接 A 的总单
* 基于总单创建任务
* 将任务落实到 C
* 接收 C 的每日填报
* 发现问题时打回 C
* 每天向 A 发起一次本分部上送

### C：现场执行层

职责是：

* 围绕分配到的任务按天填报
* 提交日报
* 被打回后修改并重新提交

这套流程是严格分层的，不允许越级直接修改。A 只能打回 B，B 只能打回 C。

## 3. 核心认识

### 3.1 任务是主业务对象，不是人

B 层默认按**任务**组织，不按**人**组织。
人是责任属性，不是当前主组织轴。页面、接口、统计的第一视角都先围绕任务。

### 3.2 任务是跨天对象，日报是单日实例

任务不是默认一天结束，而是带开始、结束时间的跨天对象。
C 的日报不是独立主对象，而是“某任务在某一天的一条记录”。
即：

 **1 个任务 → 多天日报** 。

### 3.3 正常项默认成立，异常项才处理

B 对 C 不做复杂审核状态机。
当前最小规则是：

* C 提交后即锁定
* B 没有逐条“通过”
* B 只有逐条“打回”
* 没被打回的已提交记录，默认可纳入上送

也就是：

**正常项不额外处理，异常项才处理。**

### 3.4 B→A 不是重新写一套内容，而是做一次整份上送

B 向 A 的动作，本质上不是重新生产一套新的日报内容，
而是把当天有效的 C 记录，整理为一次**B 当日上送实例**往上送。
这个实例是轻量流转载体，但必须独立存在，因为它要承载：

* 上送日期
* 上送人 / 所属 B
* 备注
* 当前状态
* 打回关系
* 本次实际上送了哪些日报

## 4. V1 最小对象

业务骨架层，V1 只看 4 个核心对象 + 1 个实现必需关联：

### 4.1 总单

A 发起的顶层安排对象。
作用：表达一次顶层工作安排，并作为后续任务来源。

### 4.2 任务

B 基于总单创建的主业务对象。
作用：承载责任归属、时间范围、后续每日填报主轴。

### 4.3 任务日报

C 围绕某任务、某一天提交的一条日报实例。
作用：记录某天对某任务的实际填报，并承载打回修正闭环。

### 4.4 B 当日上送实例

B 某一天向 A 的一次整份上送。
作用：作为 B→A 的流转载体，支持查看、打回、重提、追溯。

### 4.5 上送实例-日报关联（实现必需）

必须显式记录：

**某个 B 的某次上送，实际包含了哪些日报。**

这层关系不能靠临时查询推断。
A 看详情、缺口计算、归档追溯，都依赖这层关联。

## 5. 主流程

### 5.1 下发链

A 创建总单并下发给多个 B。
B 基于总单创建任务，并把任务落实给 C。

### 5.2 日报链

C 每天围绕任务提交日报。
提交后锁定；若被 B 打回，则在原实例上修改并重提，不新建并列记录。

### 5.3 上送链

B 每天发起一次当日上送。
系统自动纳入当天**已提交且未被打回**的日报。
B 不需要逐条勾选正常项，也不要求等所有任务都齐了才允许上报。

### 5.4 打回链

A 打回的是 B 的 **整份上送** 。
B 打回的是 C 的 **单条日报** 。
不允许越级直接修改。

## 6. 关键规则

### 6.1 应报范围规则

某任务某天是否应报，只由任务时间范围决定。
即：某日落在任务开始、结束范围内，则该日进入应报范围。

### 6.2 日报唯一规则

单任务 + 单日期 = 单日报实例。
被打回后修改原实例，不另起新条。

### 6.3 锁定规则

* C 提交日报后锁定
* 只有 B 打回后才恢复可编辑
* B 上送后，该上送实例锁定
* A 打回后，B 基于原上送实例继续处理并重提

### 6.4 自动纳入规则

B 发起上送时，系统自动挂接当天所有有效日报。
B 不手工挑选正常项。

### 6.5 缺口口径

缺口不是单独维护的一份业务内容。
口径是：

**缺口 = 应报范围 - 实际上送集合**

也就是用任务时间范围和上送关联反推，不单独建“缺口对象”。

## 7. 最小状态

### 任务

* 进行中
* 已结束

### 任务日报

* 未报
* 已提交
* 被打回

### B 当日上送实例

* 未上送
* 已上送
* 被打回

V1 不扩展更复杂状态机。

## 8. 当前明确不做

V1 暂不进入这些内容：

* 免报 / 暂停 / 恢复
* 迟报、跨天补报
* 一任务多人
* 一人多任务冲突
* 复杂权限体系
* 复杂统计报表
* 消息通知
* 完整附件体系
* 复杂操作历史
* 越级处理
* 多套审批流
* 各类例外兼容

原则是：

**凡是不属于主流程闭环必需项，V1 一律不做。**

## 9. 一句冻结结论

这套流程在技术上应这样理解：

**A 用总单做顶层安排，B 用任务承接业务主线，C 用日报承接每日事实，B 用当日上送实例承接向 A 的整份流转；系统通过任务时间范围确定应报，通过上送关联保留实送集合，通过逐级打回完成修正闭环。**
