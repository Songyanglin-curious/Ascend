## 2. 表级说明

### 2.1 `jb_production_main_order`

| 项       | 说明                                                                                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表作用   | A 创建的顶层工作安排，是整条流程的源头                                                                                                                                                         |
| 谁创建   | A                                                                                                                                                                                              |
| 主要用途 | 保存预警/安排主信息，作为 B 后续建任务的来源                                                                                                                                                   |
| 主键     | `id`                                                                                                                                                                                         |
| 关键字段 | `title`、`notice_no`、`publish_time`、`hazard_category`、`warning_level`、`impact_start_time`、`impact_end_time`、`event_summary`、`content`、`created_by`、`created_at` |
| 关联关系 | 1 个总单可下发给多个 B；1 个总单下可产生多条任务                                                                                                                                               |
| 状态字段 | 当前**没有独立状态字段**                                                                                                                                                                 |
| 当前边界 | 总单只承担顶层来源，不承担复杂审批状态                                                                                                                                                         |

---

### 2.2 `jb_production_main_order_assign`

| 项       | 说明                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 表作用   | 记录 A 把某个总单下发给哪些 B                                                                                                     |
| 谁创建   | A 下发时创建                                                                                                                      |
| 主要用途 | 支撑 B 待处理总单、全部总单、是否已承接处理                                                                                       |
| 主键     | `id`                                                                                                                            |
| 关键字段 | `main_order_id`、`receiver_b_id`、`receiver_b_name`、`receiver_b_dept_name`、`assigned_by`、`assigned_at`、`status` |
| 关联关系 | 多条 assign 归属 1 个 `main_order`；1 个 B 可收到多个总单                                                                       |
| 状态字段 | `status`，当前注释为 `pending/processed`                                                                                      |
| 当前边界 | 这是当前实现层新增对象，最早“最小 5 表”里未单独拆出                                                                             |

---

### 2.3 `jb_production_task`

| 项       | 说明                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表作用   | B 基于总单创建的主业务对象                                                                                                                           |
| 谁创建   | B                                                                                                                                                    |
| 主要用途 | 承载任务名称、时间范围、站点/班组快照，是后续日报与应报范围计算主轴                                                                                  |
| 主键     | `id`                                                                                                                                               |
| 关键字段 | `main_order_id`、`station_name`、`team_name`、`task_name`、`start_time`、`end_time`、`created_by`、`created_by_name`、`created_at` |
| 关联关系 | 多条任务归属 1 个总单；1 个任务下可有多个 `task_actor`；1 个任务下可有多条日报                                                                     |
| 状态字段 | 当前**没有独立状态字段**                                                                                                                       |
| 当前边界 | 任务仍然是主业务对象，页面/接口/统计主视角先围绕任务，不围绕人                                                                                       |

---

### 2.4 `jb_production_task_actor`

| 项       | 说明                                                                                        |
| -------- | ------------------------------------------------------------------------------------------- |
| 表作用   | 记录某任务下有哪些角色，由哪些 C 承担                                                       |
| 谁创建   | B 创建任务后配置                                                                            |
| 主要用途 | 把 WORK_OWNER、ON_DUTY_CHECK 等角色从任务主表中拆出来                                       |
| 主键     | `id`                                                                                      |
| 关键字段 | `task_id`、`actor_type`、`c_user_id`、`c_user_name`、`created_by`、`created_at` |
| 关联关系 | 多个角色归属 1 个任务；1 个角色可对应多条日报                                               |
| 状态字段 | 无                                                                                          |
| 关键约束 | `unique(task_id, actor_type)`，同一任务下同一角色类型只能出现一次                         |
| 当前边界 | 当前实现默认每种角色类型在一个任务下只配 1 个 C                                             |

---

### 2.5 `jb_production_task_actor_report`

| 项          | 说明                                                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 表作用      | C 围绕某个任务角色，在某一天提交的一条日报实例                                                                                                |
| 谁创建/修改 | C 首次填报时创建；被 B 打回后在原记录上修改重提                                                                                               |
| 主要用途    | 记录每日事实数据，承接 B 打回闭环                                                                                                             |
| 主键        | `id`                                                                                                                                        |
| 关键字段    | `task_id`、`task_actor_id`、`report_date`、各业务数值字段、`remark`、`state`、`submitted_at`、`rejected_reason`、`updated_at` |
| 关联关系    | 多条日报归属 1 个 `task_actor`；多条日报可被同一次 B 上送关联                                                                               |
| 状态字段    | `state`                                                                                                                                     |
| 关键约束    | `unique(task_actor_id, report_date)`，同一任务角色同一天只能有一条日报                                                                      |
| 当前边界    | 不允许同一天并列多条日报；被打回后修改原实例，不新建并列记录                                                                                  |

#### 状态说明

| 状态值        | 含义               | 谁可操作     | 说明                         |
| ------------- | ------------------ | ------------ | ---------------------------- |
| `CREATED`   | 草稿/初始态        | C            | 已建但未完成提交             |
| `DONE`      | 已完成但未正式上报 | C            | 当前实现保留的中间态         |
| `SUBMITTED` | 已正式提交         | C 提交后进入 | 提交后锁定，等待 B 查看      |
| `REJECTED`  | 被 B 打回          | B 打回后进入 | C 可在原记录上修改并再次提交 |


---

### 2.6 `jb_production_b_daily_submission`

| 项          | 说明                                                                                                             |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| 表作用      | B 某一天向 A 发起的一次整份上送实例                                                                              |
| 谁创建/提交 | B                                                                                                                |
| 主要用途    | 作为 B→A 的流转载体，承载备注、提交时间、A打回原因、重提                                                        |
| 主键        | `id`                                                                                                           |
| 关键字段    | `b_user_id`、`submission_date`、`remark`、`state`、`submitted_at`、`rejected_reason`、`updated_at` |
| 关联关系    | 1 条 submission 可关联多条日报                                                                                   |
| 状态字段    | `state`                                                                                                        |
| 关键约束    | `unique(b_user_id, submission_date)`，一个 B 一天只保留一份上送实例                                            |
| 当前边界    | A 打回的是整份 submission；B 重提不是新建一份，而是在原 submission 上重提                                        |

#### 状态说明

| 状态值        | 含义               | 谁可操作     | 说明               |
| ------------- | ------------------ | ------------ | ------------------ |
| `CREATED`   | 已创建但未正式上送 | B            | 当前实现保留初始态 |
| `SUBMITTED` | 已上送给 A         | B 提交后进入 | 正常上送完成       |
| `REJECTED`  | 被 A 打回          | A 打回后进入 | B 在原实例上重提   |

**A 打回 submission 时，不清理 submission 与日报的关联；真正清旧关联发生在 B 重提之前。**

---

### 2.7 `jb_production_b_daily_submission_actor_report_rel`

| 项       | 说明                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 表作用   | 记录某次 B 上送实例到底带了哪些角色日报                                       |
| 谁生成   | 系统在 B 上送/重提时生成或重建                                                |
| 主要用途 | 支撑 A 看详情、缺口计算、归档追溯、重提覆盖                                   |
| 主键     | `id`                                                                        |
| 关键字段 | `submission_id`、`task_actor_report_id`                                   |
| 关联关系 | 多条 rel 归属 1 个 submission；每条 rel 指向 1 条日报                         |
| 状态字段 | 无                                                                            |
| 关键约束 | `unique(submission_id, task_actor_report_id)`，同一上送中同一日报只关联一次 |
| 当前边界 | 这张表不能省，不能靠事后再查条件反推“当次送了哪些日报”                      |

## 3. 主键与关联关系

### 3.1 关系总图（文字版）

| 上游表                 | 下游表                                  | 关系 | 关联字段                                             |
| ---------------------- | --------------------------------------- | ---- | ---------------------------------------------------- |
| `main_order`         | `main_order_assign`                   | 1:N  | `main_order_assign.main_order_id -> main_order.id` |
| `main_order`         | `task`                                | 1:N  | `task.main_order_id -> main_order.id`              |
| `task`               | `task_actor`                          | 1:N  | `task_actor.task_id -> task.id`                    |
| `task`               | `task_actor_report`                   | 1:N  | `task_actor_report.task_id -> task.id`             |
| `task_actor`         | `task_actor_report`                   | 1:N  | `task_actor_report.task_actor_id -> task_actor.id` |
| `b_daily_submission` | `b_daily_submission_actor_report_rel` | 1:N  | `rel.submission_id -> submission.id`               |
| `task_actor_report`  | `b_daily_submission_actor_report_rel` | 1:N  | `rel.task_actor_report_id -> report.id`            |

### 3.2 核心业务链

可以压成这一条：

`main_order`
→ `main_order_assign`
→ `task`
→ `task_actor`
→ `task_actor_report`
→ `b_daily_submission`
→ `b_daily_submission_actor_report_rel`

但真正的“主业务事实链”是：

**总单 → 任务 → 任务角色日报 → B当日上送 → 上送关联**

其中：

* `main_order_assign` 解决“发给谁”
* `task_actor` 解决“谁干什么角色”

这两张更偏实现组织层。

## 4. 状态体系整理

### 4.1 业务口径状态

| 对象      | 业务口径状态             |
| --------- | ------------------------ |
| 任务      | 进行中 / 已结束          |
| 日报      | 未报 / 已提交 / 被打回   |
| B当日上送 | 未上送 / 已上送 / 被打回 |

这是你对外讲流程、讲主规则时最稳的口径。

### 4.2 当前真实实现状态

| 表                                                    | 当前状态字段 | 当前状态值                                      |
| ----------------------------------------------------- | ------------ | ----------------------------------------------- |
| `jb_production_main_order`                          | 无           | 无                                              |
| `jb_production_main_order_assign`                   | `status`   | `pending`/`processed`                       |
| `jb_production_task`                                | 无           | 无                                              |
| `jb_production_task_actor`                          | 无           | 无                                              |
| `jb_production_task_actor_report`                   | `state`    | `CREATED`/`DONE`/`SUBMITTED`/`REJECTED` |
| `jb_production_b_daily_submission`                  | `state`    | `CREATED`/`SUBMITTED`/`REJECTED`          |
| `jb_production_b_daily_submission_actor_report_rel` | 无           | 无                                              |

### 4.3 状态流转

#### 任务角色日报

`无记录` → `CREATED` → `DONE` / `SUBMITTED`
`SUBMITTED` → `REJECTED`
`REJECTED` → `SUBMITTED`

#### B当日上送

`无记录` → `CREATED` → `SUBMITTED`
`SUBMITTED` → `REJECTED`
`REJECTED` → 删除旧 rel → 重挂新 rel → `SUBMITTED`

这条“重提不是新建 submission，而是复用原 submission”在前端最小流程文档中已经明确。

## 5. 关键唯一约束与业务含义

| 表                                                    | 约束                                            | 含义                               |
| ----------------------------------------------------- | ----------------------------------------------- | ---------------------------------- |
| `jb_production_b_daily_submission`                  | `unique(b_user_id, submission_date)`          | 一个 B 一天只保留一份上送实例      |
| `jb_production_b_daily_submission_actor_report_rel` | `unique(submission_id, task_actor_report_id)` | 同一份上送里同一条日报只关联一次   |
| `jb_production_main_order_assign`                   | `unique(main_order_id, receiver_b_id)`        | 同一总单不会重复下发给同一个 B     |
| `jb_production_task_actor`                          | `unique(task_id, actor_type)`                 | 同一任务下同一角色类型只能配置一次 |
| `jb_production_task_actor_report`                   | `unique(task_actor_id, report_date)`          | 同一任务角色同一天只能有一条日报   |

其中最重要的 3 个冻结约束仍然是：

* 日报单日唯一
* B 单日 submission 唯一
* submission 与日报关联唯一

这些约束直接决定后续接口怎么写。

## 6. 这版表结构最重要的实现说明

### 6.1 任务仍是主轴，不是人

虽然拆出了 `task_actor`，但这不是把主轴改成“人”。
只是把“任务下的角色责任”显式化。主链仍然围绕任务。

### 6.2 “未报 / 未上送”多数是查询态，不一定是存储态

* 未报：通常是应报范围内没有日报记录
* 未上送：通常是当天没有 submission，或 submission 还未到 `SUBMITTED`

所以不是所有业务状态都必须落成表字段。

### 6.3 A 打回不清关联，B 重提才重建关联

这是当前实现里最容易做错的一点。
A 打回 submission 后，关联 rel 仍然保留；真正删旧 rel、重挂新 rel，是 B 重提时做的事务动作。

### 6.4 当前“任务表无状态”是可以成立的

因为任务进行中/已结束，可以先由 `start_time`、`end_time` 和查询日期推导。
所以你当前没单独做 `task.status`，在 V1 是能成立的。这个和最早“建议可有状态字段”并不冲突，只是实现取了更轻的方案。这个判断是基于你当前 DDL与既有规则做的实现推断。
