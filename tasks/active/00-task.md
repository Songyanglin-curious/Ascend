# 任务目标

1. **场景节点化封装**：将“推进场景”封装为一个可挂载到 Node 的独立执行单元。
2. **节点最小时序**：规范 Node 内部时序为：`进入节点` ➔ `执行推进场景` ➔ `返回场景原始结果` ➔ `节点结束`。
3. **最小树承载**：建立 Node 的最小父子树承载能力，使多个 Node 能以树关系组织。

## 背景

当前“推进场景”本身已经形成独立工作流。本批不继续扩展场景内部逻辑，只先解决两个基础问题：

1. 场景如何装进一个 Node
2. 多个 Node 如何形成最小树结构

本批只关心：

- Node 如何承载场景
- Tree 如何维护父子关系

场景退出后的总结、派生新节点、人工路由等后处理逻辑，不纳入本批。

## 本次范围

- 为 Node 定义承载推进场景的最小结构
- 让 Node 能执行推进场景并保留场景原始输入输出
- 为 Tree 定义最小结构，Tree 只维护父子关系：`parentId / childrenIds`
- 支持以下最小操作：
  - `createNode`
  - `getNodeById`
  - `createRoot`
  - `createChild`
  - `getChildren`

## 本次不做

- 不做 UI
- 不做总结生成
- 不做新节点提取
- 不做人工确认与动态路由
- 不做回扫关系
- 不做图结构
- 不做复杂树操作（删除整棵子树、移动节点、重排等）

## 硬约束

- Node 与场景解耦
- Tree 只维护父子关系，不承载节点内容
- Node 承载具体内容，并通过 id 与 Tree 关联
- 本批只做最小闭环，不提前扩展后处理能力

## 交付物

- Node 最小数据结构
- Tree 最小数据结构
- Node 执行推进场景的最小时序
- Node / Tree 最小操作模块：
  - `createNode`
  - `getNodeById`
  - `createRoot`
  - `createChild`
  - `getChildren`

## 完成标志

- 能创建一个承载推进场景的 Node
- 进入 Node 后能执行推进场景，并保留场景原始输入输出
- 能创建根节点与子节点
- 能通过 Tree 组织多个 Node 的父子关系
- 能按 id 获取 Node
- 能获取某节点的直接子节点

## 已决定的设计约束

- 当前主结构先用树，不处理图关系
- Tree 与 Node 内容分离
- 场景退出后的后处理逻辑不属于本批
