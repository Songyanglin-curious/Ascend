# 页面内候选确认与子节点创建

## 目标

当前系统已经具备：

- SQLite 持久化
- 树关系维护
- 候选子节点提取与确认能力
- 只读页面展示层

但当前“候选确认 -> 创建子节点 -> 维护树关系”这条链路仍然主要依赖 CLI，页面只能看，不能接住这一步交互。
本里程碑目标是把这条交互搬进页面，让用户可以直接在页面中完成候选确认并创建真实子节点。

## 本里程碑要解决的问题

1. 需要在页面中看到当前选中节点对应的候选子节点，而不是回到 CLI 才能确认。
2. 需要在页面中支持一次选择多个候选，并批量创建真实 child node。
3. 候选确认完成后，页面中的树图需要立即刷新，反映新挂载的子节点。
4. 页面操作必须复用现有业务语义，不能另造一套与 CLI 不一致的创建逻辑。

## 当前阶段范围

本里程碑只做以下页面内交互：

1. 展示当前选中节点的候选子节点列表
2. 支持多选候选
3. 支持确认创建真实子节点
4. 创建成功后刷新树图和当前节点详情

## 页面交互要求

### 候选列表展示

- 选中某个节点后，页面应能看到该节点对应的候选子节点列表
- 每个候选至少展示：
  - title
  - summary
  - type
  - reason
  - evidence
- 若当前节点没有候选，页面应有明确空状态提示

### 候选确认

- 页面必须支持一次选择多个候选
- 页面确认语义应与当前 CLI 一致：
  - 可以确认多个
  - 可以一个都不选
- 确认动作触发后，系统应创建真实 child node，并挂到当前父节点下

### 创建后的页面联动

- 创建成功后，树图必须刷新
- 新子节点应出现在当前父节点下
- 页面右侧当前选中节点上下文应保持稳定，不因为刷新而丢失

## 技术方向

- 继续沿用当前只读页面骨架：
  - `Vite + React`
  - `React Flow(@xyflow/react)` 展示树
  - assistant-ui 展示聊天历史
- 在现有展示层基础上增加“候选展示与确认”模块
- 页面通过本地 API 与后端交互，不直接访问 SQLite

## 展示层结构要求

在已有模块基础上，新增或扩展以下模块边界：

1. 页面容器模块
   - 负责选中节点状态
   - 负责候选加载与确认后的刷新
2. 树图展示模块
   - 继续只负责树结构展示与节点选中
3. 聊天展示模块
   - 继续只负责聊天历史展示
4. 候选展示与确认模块
   - 负责候选列表展示
   - 负责多选状态
   - 负责确认按钮与提交状态
5. 数据查询与写入适配模块
   - 负责候选读取
   - 负责确认请求
   - 负责把返回结果映射成页面可消费模型

## 本里程碑不做

- 不做页面内继续推进 workflow
- 不做页面内发送消息
- 不做节点编辑
- 不做拖拽改树
- 不做多棵树管理
- 不做页面权限与用户体系
- 不重构现有 SQLite schema

## 验收标准

- 选中某个节点后，页面能展示该节点的候选子节点列表
- 页面支持一次选择多个候选
- 页面确认后能创建真实子节点并维护树关系
- 树图在确认成功后能立即刷新
- 页面交互语义与现有 CLI 候选确认保持一致
- 不改变现有只读聊天展示与树图主路径语义

## 备注

- 本里程碑优先解决“从只读到可确认”的闭环，不扩成完整页面工作台。
- 后续若要继续推进页面内 workflow、节点编辑或多树管理，再在此基础上继续拆里程碑。
