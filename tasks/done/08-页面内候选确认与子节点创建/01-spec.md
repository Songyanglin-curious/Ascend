# 01-spec：页面内候选确认与子节点创建

## 摘要

- 本里程碑在现有“只读页面展示层”之上，补齐“候选展示 -> 多选确认 -> 创建真实子节点 -> 刷新树图”的最小交互闭环。
- 页面交互必须复用当前 CLI 的业务语义，不能另造一套候选确认和子节点创建规则。
- 本 spec 只冻结页面行为、模块边界、读写数据语义、失败路径和验收标准，不进入文件命名、接口地址、状态管理实现和组件样式细节，这些留到 `02-plan.md`。

## 目标与范围

本里程碑只覆盖以下能力：

1. 页面能展示当前选中节点对应的候选子节点列表。
2. 页面能对候选子节点执行多选确认。
3. 页面确认后能创建真实 child node，并维护树关系。
4. 页面在创建成功后能刷新当前树视图与当前节点上下文。

本里程碑明确不做：

- 不做页面内继续推进 workflow
- 不做页面内发送消息
- 不做节点编辑
- 不做拖拽改树
- 不做多棵树管理
- 不改现有 SQLite schema
- 不重写现有 CLI 候选确认逻辑的业务语义

## 事实基础

- 当前系统已经具备：
  - SQLite 持久化
  - `nodes / tree_state / tree_relations / child_candidate_events`
  - 候选子节点提取能力
  - 批量候选确认并创建子节点能力
  - 只读页面展示层
- 当前页面已经具备：
  - 树图展示
  - 聊天历史展示
  - 选中节点联动
- 当前页面还不具备：
  - 候选列表展示
  - 页面内候选确认
  - 页面触发子节点创建

## 核心原则

### 1. 页面只新增“确认创建”能力，不改业务判定语义

- 页面不负责提炼新的候选规则。
- 页面不自行决定哪些候选应该被创建。
- 页面只承载：
  - 展示候选
  - 选择候选
  - 提交确认

### 2. 候选列表与树图、聊天区解耦

- 树图模块继续只负责节点关系和节点选中。
- 聊天模块继续只负责聊天历史展示。
- 候选展示与确认必须是独立模块，不能把候选 UI 混进树图或聊天组件内部。

### 3. 页面读写边界分离

- 页面读取树和聊天历史，继续通过只读 read model。
- 页面提交候选确认，必须走独立写入接口。
- 写入完成后，页面通过重新读取 read model 刷新，而不是在前端本地伪造树状态。

### 4. 页面写入以“父节点上下文”驱动

- 候选列表总是绑定某个当前选中父节点。
- 页面确认动作必须显式带上父节点身份。
- 若当前选中节点变化，候选显示上下文必须同步切换。

## 页面结构契约

### 1. 页面容器模块

职责：

- 管理当前选中节点
- 协调树图、聊天、候选区域
- 负责候选读取和确认成功后的整体刷新
- 负责加载态、提交态、错误态

不负责：

- 不直接拼装底层数据库结构
- 不直接写树图节点映射细节
- 不直接写聊天消息映射细节

### 2. 树图展示模块

职责：

- 展示当前树
- 抛出节点选中事件

不负责：

- 不负责候选展示
- 不负责确认提交
- 不负责聊天渲染

### 3. 聊天展示模块

职责：

- 展示当前选中节点的聊天历史

不负责：

- 不负责候选展示
- 不负责候选确认

### 4. 候选展示与确认模块

职责：

- 展示当前节点对应的候选列表
- 支持多选
- 支持“确认创建”动作
- 展示空状态、提交中状态和错误状态

不负责：

- 不负责树图刷新逻辑本身
- 不负责直接修改前端树结构

### 5. 数据适配模块

职责：

- 定义候选读模型与候选写入结果模型
- 负责页面读接口和写接口的请求封装
- 负责把服务端返回结果转成页面 ViewModel

## 数据语义契约

### 1. 页面候选读模型

页面在选中某个节点后，至少要能读取：

- 父节点 id
- 候选数组

每个候选至少能表达：

- `candidateId`
- `title`
- `summary`
- `type`
- `reason`
- `evidence`

说明：

- 这里冻结的是页面必须可消费的语义，不强钉服务端最终字段命名。
- 候选为空数组是合法结果，不是错误。

### 2. 页面候选确认写模型

页面提交确认时，至少要能表达：

- 当前父节点 id
- 用户确认通过的多个 `candidateId`

说明：

- 空选择是合法提交，语义等同于“本次不创建任何子节点”。
- 页面不允许提交不属于当前父节点的 `candidateId`。

### 3. 页面写入结果模型

确认接口返回结果至少要能表达：

- 父节点 id
- 实际创建的子节点列表
- 是否创建成功

若没有创建任何子节点，返回也必须是显式可判定结果，而不是靠空白或静默失败表达。

## 页面行为契约

### 1. 初始加载

- 页面首次打开时继续读取只读页面模型。
- 若存在 root，默认选中 root。
- 默认同时展示：
  - root 聊天历史
  - root 候选子节点区域

### 2. 节点切换

- 用户点击树图中的其他节点时：
  - 当前选中节点切换
  - 聊天区域切换到该节点历史
  - 候选区域切换到该节点候选列表

### 3. 候选为空

- 若当前节点没有候选，候选区域显示明确空状态。
- 空状态不视为错误。

### 4. 多选确认

- 用户可以一次选择多个候选。
- 用户可以一个都不选并提交。
- 提交前页面必须基于当前节点上下文显示选中结果。

### 5. 提交中

- 候选确认提交过程中，页面应有明确提交中状态。
- 提交中时，应阻止重复提交。

### 6. 提交成功

- 成功后页面必须重新拉取只读页面模型。
- 树图中应出现新创建的 child node。
- 当前选中父节点应保持不变。
- 聊天区继续显示当前父节点聊天历史，不自动切到新子节点。

### 7. 提交失败

- 页面必须显示显式错误状态。
- 失败后不得伪造树图更新。
- 失败后当前多选状态是否保留，留到 `02-plan.md` 决定；但必须有一致策略，不能随机。

## 后端交互契约

### 1. 读接口

至少需要一类接口，用于读取某个父节点对应候选列表。

语义要求：

- 输入：父节点 id
- 输出：该父节点的候选数组

### 2. 写接口

至少需要一类接口，用于确认候选并创建真实子节点。

语义要求：

- 输入：
  - 父节点 id
  - 已选择 candidateId 数组
- 输出：
  - 创建结果
  - 新建子节点语义结果

### 3. 页面刷新方式

- 候选确认写入成功后，页面必须重新读取 read model。
- 页面不得只在本地前端拼接一个“假 child node”来冒充成功。

## 失败与边界

### 1. 当前节点无候选

- 合法空状态
- 不报错

### 2. 候选读取失败

- 页面显示显式错误提示
- 不影响树图和聊天区继续显示当前已读内容

### 3. 提交时父节点无效

- 视为显式错误
- 不创建任何子节点

### 4. 提交时 candidateId 非法

- 视为显式错误
- 不创建任何子节点

### 5. 后端创建或挂树失败

- 视为显式错误
- 页面不伪造成功结果

### 6. 提交成功但创建数为 0

- 视为合法结果
- 等同于用户本次未确认任何候选

## 最小验收场景

1. 打开页面后，若 root 存在，默认展示 root 聊天历史和 root 候选列表。
2. 点击不同节点时，候选区域跟随切换到该节点的候选列表。
3. 当前节点无候选时，候选区域显示空状态。
4. 当前节点存在多个候选时，页面支持多选。
5. 确认多个候选后，系统批量创建多个 child node，并刷新树图。
6. 创建成功后，当前父节点仍保持选中，聊天历史不丢失。
7. 提交失败时，页面显示显式错误，树图不出现伪造节点。

## 默认假设

- 当前仍然是单树模式。
- 页面候选确认直接复用现有“候选确认后创建子节点”业务语义。
- 本里程碑不要求页面直接展示 `child_candidate_events` 历史审计记录，只要求展示“当前可确认候选”。
- 候选提取链路仍由后端现有能力负责；本 spec 不冻结候选是“现算”还是“读取已缓存结果”，只冻结页面侧读写行为与结果语义。
