# 任务目标

1. 从一个节点对话结束后返回的原始对话内容中提取出来候选子节点
2. 候选子节点经过人确定后正式生成真正的节点并维护对应的树关系

## 背景

目前已经有了一个推进场景的工作流 并且也有一个场景装进到Node  Node已经可以形成一个树结构

本批只先解决两个基础问题：

1. 一个节点结束后调用AI从中提取出来候选子节点
2. 候选子节点经过人确认后正式生成真正的节点并维护对应的树关系

## 本次范围

- 创建一个提取子节点的Agent 与工作流无关
- 提取候选子节点Agent需要限制AI输出可供后续使用的Json格式
- 提取子节点的提示词参考

```md


# 角色：Child Candidate Extractor

你的唯一任务：

**从当前节点的对话记录中，提取“值得成为子节点的候选分支”。**

你不是在总结，不是在扩展，不是在给方案。
你只做一件事：**把对话里的潜在分支结构化。**

---

## 一、提取原则（强约束）

1）只提“可独立推进”的分支

* 必须是可以单独成为一个节点的问题/方向
* 纯描述、重复表达、细节补充 → 不要提

2）优先提三类

* 新问题（隐含或显式）
* 分支方向（不同路径/策略）
* 关键约束（会改变推进方式的限制）

3）禁止污染

* 不要改写原意
* 不要补充你自己的想法
* 不要推导新方向（只提取，不创造）

4）去重与合并

* 语义重复的合并为一个
* 同一方向的不同表述只保留一个

5）控制数量

* 默认 3–6 个
* 不足就少给，不强凑

---

## 二、输出格式（严格遵守）

```json
[
  {
    "title": "一句话子节点名称",
    "summary": "这个分支在讨论什么（保持贴近原话）",
    "type": "question | direction | constraint",
    "reason": "为什么它值得成为子节点（一句话）",
    "evidence": "对应原对话中的关键表达（可截取或转述）"
  }



```

- 提取后的时候选节点需要人来确认是否添加
- 确认通过后生成Node与维护树关系

## 本次不做

- 不做 UI
- 不做总结生成
- 不做回扫关系
- 不做图结构
- 不做复杂树操作（删除整棵子树、移动节点、重排等）

## 硬约束

- 提取子节点的Agent 必须输出可供后续使用的JSON格式
- 候选子节点必须要经过人进行判断
- 人允许候选子节点添加后必须能够正常创建子节点
- 必须能够正确维护树关系
- 提取子节点的Agent 要与场景工作流解耦

## 交付物

- 候选子节点最小数据结构
- 提取子节点的Agent
- Node 执行推进场景的结束 -> 提取候选子节点->人确定->生成对应的Node->维护树关系  最小时序

## 完成标志

- 能够在场景结束后正确提取候选子节点
- 候选子节点必须要经过人确认
- 确认后能够正确创建Node
- 创建node后能正确维护树关系

## 已决定的设计约束

- **子节点生成必须是独立逻辑（独立阶段 / 独立处理单元）** ，不能混在 Scene 执行或树结构里
