# 页面四区可收起/展开

## 摘要

- 当前页面已经具备 4 个主要展示区块：
  - 左侧树图区
  - 右侧聊天历史区
  - 右侧继续推进输入区
  - 右侧候选确认区
- 当前主要问题不是业务链路缺失，而是空间分配不灵活：
  - 输入区高度偏窄
  - 右侧内容容易互相挤压
  - 左侧树图区在某些情况下可用空间不足
- 本里程碑目标是给这 4 个区块补上“可收起/展开”的页面交互，让用户能按当前工作重点临时调整可视空间。

## 目标

页面需要支持以下最小交互：

1. 左侧树图区可整体收起与展开
2. 右侧三块区域可分别进行上下收起与展开
3. 收起/展开后不影响当前选中节点、聊天历史、候选状态与 workflow 状态
4. 展开后原区块内容继续显示，不重新定义业务语义

## 当前问题

1. 输入区空间偏小，长文本输入体验差
2. 聊天历史、输入区、候选区固定占位，无法按当前任务重点调整
3. 左侧树图区与右侧内容区无法根据工作阶段动态分配宽度

## 本里程碑范围

本次只做：

1. 左侧整列收起/展开
2. 右侧聊天区收起/展开
3. 右侧输入区收起/展开
4. 右侧候选区收起/展开
5. 收起/展开后的页面布局重排
6. 对应的最小提示文案与状态反馈

## 本里程碑不做

1. 不改树、聊天、候选、推进的业务逻辑
2. 不新增拖拽调节尺寸
3. 不做面板顺序重排
4. 不做布局持久化到数据库
5. 不做移动端专门交互重设计
6. 不改 SQLite schema

## 关键要求

### 1. 左右分层语义明确

- 左侧树图区视为一个整块
- 右侧三个区块视为另一整块中的三个垂直子块
- 左侧的交互是“左右展开/收起”
- 右侧三个区块的交互是“上下展开/收起”

### 2. 收起是布局动作，不是数据重置

- 收起区块后，只隐藏或压缩展示，不得清空内部状态
- 再展开时，应恢复原区块内容
- 收起/展开不得触发额外业务写操作

### 3. 区块之间不能互相污染

- 收起树图区，不影响右侧三块的业务状态
- 收起聊天区，不影响输入区和候选区
- 收起输入区，不影响聊天历史和候选区
- 收起候选区，不影响聊天历史和输入区

### 4. 页面必须给出明确控制入口

- 每个可收起区块都要有明确的展开/收起入口
- 控制入口必须与对应区块强绑定，避免歧义

## 验收标准

1. 左侧树图区可以收起，再展开后恢复正常显示
2. 右侧聊天区可以收起，再展开后恢复正常显示
3. 右侧输入区可以收起，再展开后恢复正常显示
4. 右侧候选区可以收起，再展开后恢复正常显示
5. 任一区块收起/展开不丢失当前选中节点与已有历史数据
6. 输入区展开后可获得比当前更充足的空间
7. 页面主链能力不回退：树展示、聊天展示、继续推进、候选确认都仍可用

## 默认假设

- 当前页面仍以桌面端体验优先
- 当前这批只解决“空间分配与可视切换”，不引入新的业务动作
- 展示状态可以先保存在前端本地组件状态中，不要求跨刷新持久化
