# 01-spec：页面四区可收起/展开

## 摘要

- 本里程碑只解决页面布局层的可视空间控制问题，不改业务链路。
- 页面继续保持 4 个核心区块：
  - 左侧树图区
  - 右侧聊天历史区
  - 右侧继续推进输入区
  - 右侧候选确认区
- 本 spec 冻结的是区块收起/展开行为、状态语义、布局联动与验收标准，不进入具体实现细节。

## 目标与范围

本里程碑只覆盖以下能力：

1. 左侧树图区可整体收起与展开
2. 右侧聊天历史区可收起与展开
3. 右侧继续推进输入区可收起与展开
4. 右侧候选确认区可收起与展开
5. 收起/展开后页面布局自动重排

本里程碑明确不做：

1. 不改树、聊天、推进、候选确认的业务语义
2. 不引入拖拽调节宽高
3. 不改变右侧三块的上下顺序
4. 不把展开状态持久化到数据库
5. 不专门重做移动端布局

## 事实基础

- 当前页面结构是：左一列树图，右一列三段垂直面板。
- 左侧树图区承担节点关系可视化。
- 右侧三块分别承担：
  - 聊天历史只读展示
  - 当前节点继续推进输入
  - 当前节点候选确认
- 当前页面问题是输入区可用空间偏小，且各区块高度固定，无法根据任务重点调整。

## 核心原则

### 1. 收起/展开只影响展示，不影响业务状态

- 收起区块不得清空内部组件状态
- 收起区块不得触发写库
- 再展开时，继续显示已有内容

### 2. 左右与上下是两层不同语义

- 左侧树图区作为一个独立主区块，只允许整体左右收起/展开
- 右侧三个区块作为同一侧栏内的三个子区块，只允许分别上下收起/展开

### 3. 页面不能因为收起而“丢上下文”

- 当前选中节点必须保持
- 当前聊天历史必须保持
- 当前候选状态必须保持
- 输入区已有未提交文本，默认在本节点内保持；若该区块只是收起，不应丢失

### 4. 控制入口必须就近可见

- 每个可收起区块都需要自己的切换入口
- 左侧主区块的入口应绑定左侧主区块
- 右侧三个子区块各自有自己的切换入口

## 页面结构契约

### 1. 左侧主区块

职责保持不变：

- 展示树节点与关系
- 响应节点选中

新增要求：

- 可切换为“展开态”或“收起态”
- 收起态时，右侧区域获得更多横向空间
- 展开态时，恢复原有双列布局

### 2. 右侧侧栏容器

职责保持不变：

- 承载聊天历史、输入区、候选区

新增要求：

- 右侧整体始终保留
- 右侧内部三个子区块可独立收起/展开

### 3. 聊天历史区

职责保持不变：

- 展示当前节点完整聊天历史

新增要求：

- 收起后不显示正文内容
- 展开后恢复原有历史内容与滚动区域

### 4. 继续推进输入区

职责保持不变：

- 承载输入框、发送并推进、结束本轮等交互

新增要求：

- 展开态时应获得足够的输入空间
- 收起后不显示输入正文区
- 若只是收起再展开，未发送文本不应丢失

### 5. 候选确认区

职责保持不变：

- 展示当前节点候选
- 多选确认并创建子节点

新增要求：

- 收起后不显示候选列表正文
- 展开后恢复已有候选状态与勾选状态

## 状态语义

### 1. 左侧主区块状态

- `expanded`
- `collapsed`

### 2. 右侧三个子区块状态

每个子区块独立维护：

- `expanded`
- `collapsed`

### 3. 默认状态

- 左侧树图区默认展开
- 右侧聊天历史区默认展开
- 右侧输入区默认展开
- 右侧候选区默认展开

## 布局行为契约

### 1. 左侧树图区收起时

- 页面切换为“右侧优先”的布局
- 右侧区域横向空间增大
- 左侧不再占用原本主列宽度，只保留最小控制入口

### 2. 左侧树图区展开时

- 页面恢复双列布局
- 树图区重新占据左列主空间

### 3. 右侧子区块收起时

- 被收起区块正文折叠
- 其他右侧区块获得更多纵向空间
- 区块标题与切换入口仍保留

### 4. 右侧子区块展开时

- 恢复原区块正文
- 右侧三块重新按当前布局分配空间

## 失败与边界

### 1. 收起/展开不是异步操作

- 这是一类纯前端交互
- 不应引入 loading
- 不应依赖 API 返回

### 2. 收起/展开不是路由切换

- 不刷新页面
- 不重建整个 read model
- 不把区块状态误当成数据刷新行为

### 3. 极端情况

- 若右侧三个区块全部收起，仍需保留各自标题与展开入口
- 若左侧树图区收起，仍需保留展开入口，不能让用户失去返回方式

## 最小验收场景

1. 左侧树图区可收起，右侧横向空间明显增大。
2. 左侧树图区可重新展开，树图恢复正常显示。
3. 右侧聊天历史区可收起与展开，聊天内容不会丢失。
4. 右侧输入区可收起与展开，未发送文本不会因收起而丢失。
5. 右侧候选区可收起与展开，候选列表与勾选状态不会因收起而丢失。
6. 收起/展开任一区块后，当前选中节点保持不变。
7. 页面主链能力不回退：树展示、聊天展示、继续推进、候选确认仍可正常工作。

## 默认假设

- 当前优先支持桌面端页面。
- 展开状态先保存在前端组件状态中即可。
- 本批不要求把布局状态写入 URL、数据库或本地持久化。
