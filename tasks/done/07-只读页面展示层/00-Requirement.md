# 只读页面展示层

## 目标

当前系统已经具备：

- SQLite 持久化
- 树关系维护
- 场景原始结果保存
- 候选子节点提取与确认

但当前主要交互仍然依赖 CLI，人工理解成本高，验收效率低。
本里程碑目标是补一层只读页面展示，先解决“看不见”的问题，不在这一阶段引入页面操作。

## 本里程碑要解决的问题

1. 需要在页面中直观看到当前树结构，而不是只靠 CLI 打印快照。
2. 需要在页面中看到某个节点对应的聊天历史，而不是只在终端里阅读原始输出。
3. 展示层必须模块化，避免把树图、聊天、数据映射与页面容器混成一个大文件。

## 技术方向

- 树节点与关系展示：使用 React Flow（@xyflow/react）
- 聊天历史展示：使用 assistant-ui

## 当前阶段范围

本里程碑只做只读展示，包含两块：

1. 树节点展示
2. 聊天对话框展示

## 树节点展示要求

- 展示当前 root 与 child 的树关系
- 基于现有节点与树关系数据映射生成可视化图
- 支持选中某个节点
- 选中状态应反馈到右侧详情或聊天展示区
- 当前不要求页面内新增、删除、拖拽、编辑节点

## 聊天对话框展示要求

- 展示当前选中节点对应的聊天历史
- 使用对话框形式，而不是原始 JSON 文本直出
- 当前阶段只读，不提供发送消息能力
- 当前阶段不在页面内继续推进 workflow

## 展示层结构要求

展示层必须分模块，至少区分：

1. 页面容器模块
   - 负责整体布局
   - 负责当前选中节点状态
2. 树图展示模块
   - 负责 React Flow 渲染
   - 负责节点与边的展示
   - 负责抛出节点选中事件
3. 聊天历史展示模块
   - 负责 assistant-ui 或等价只读聊天组件渲染
4. 数据查询或适配模块
   - 负责把现有数据结构转换成页面可消费的 ViewModel
5. 类型与映射模块
   - 负责页面层使用的类型定义与映射函数

## 本里程碑不做

- 不做页面内发送消息
- 不做页面内候选确认
- 不做页面内创建子节点
- 不做页面内继续推进场景
- 不做节点编辑
- 不做拖拽改树
- 不做权限或用户体系
- 不做页面写操作 API

## 验收标准

- 页面可以看到当前树结构
- 点击树节点后，右侧能切换到对应节点的聊天历史
- 聊天历史以对话形式展示，不是直接输出数据库原始 JSON
- 页面结构是模块化的，不是所有逻辑堆在单文件里
- 不改变现有 CLI 主流程的业务语义

## 备注

- 当前阶段优先“可读、可验收、结构清晰”，不追求一次做全交互。
- 后续若要扩展页面操作，再以此只读展示层为基础继续演进。
