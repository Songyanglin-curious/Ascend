# 01-spec：只读页面展示层

## 摘要

- 本里程碑只解决“看不见”的问题：把当前树结构和节点聊天历史从 CLI 迁到页面只读展示。
- 技术方向固定为：
  - 树图展示：`React Flow`（`@xyflow/react`）
  - 聊天历史展示：`assistant-ui`
- 本 spec 只冻结页面行为、模块边界、展示数据语义与验收标准，不进入目录结构、具体路由、构建工具、状态库、接口文件名与样式实现，这些留到 `02-plan.md`。

## 目标与范围

本里程碑只覆盖以下能力：

1. 页面能展示当前树结构。
2. 页面能展示当前选中节点对应的聊天历史。
3. 页面能在树节点切换时联动切换右侧聊天内容。
4. 展示层结构必须模块化，而不是把布局、树图、聊天、数据映射全部堆进一个页面文件。

本里程碑范围内：

- 实现一个只读页面容器
- 实现树图展示模块
- 实现聊天历史展示模块
- 实现页面层所需的数据查询/适配能力
- 实现页面层所需的 ViewModel 与映射逻辑

本里程碑明确不做：

- 不做页面内发送消息
- 不做页面内继续推进 workflow
- 不做页面内候选确认
- 不做页面内创建子节点
- 不做节点编辑
- 不做拖拽改树
- 不做页面写操作 API
- 不改变现有 CLI 主流程语义

## 事实基础

- 当前系统已经有：
  - SQLite 持久化
  - `nodes / tree_state / tree_relations / child_candidate_events`
  - 场景原始结果保存
  - CLI 下的树快照与聊天原始记录
- 当前页面里程碑不负责新增业务数据，只负责展示已有数据。
- 当前树模式仍是单树模式，不涉及多棵树切换。

## 核心设计原则

### 1. 页面先只读，禁止偷带操作

- 页面在本里程碑中只做展示，不承载任何业务写操作。
- 树图点击只改变页面选中状态，不改变数据库。
- 聊天区只展示消息，不提供提交能力。

### 2. 展示层必须分模块

- 页面容器、树图展示、聊天展示、数据适配、类型映射必须解耦。
- 不允许出现一个页面文件同时负责：
  - 查数据
  - 转换数据
  - 管理选中状态
  - 渲染树图
  - 渲染聊天线程

### 3. 页面只消费 ViewModel，不直接消费底层数据库结构

- 页面组件层不直接依赖 SQLite 表结构。
- 页面组件应消费页面专用 ViewModel。
- `SceneNode`、树关系、原始消息到 UI 数据的转换，必须在适配层完成。

### 4. 当前页面只承载单树视图

- 页面只展示当前唯一 root 及其子节点关系。
- 不引入树列表、树切换、工作区切换。

## 页面结构契约

### 1. 页面容器模块

职责：

- 负责页面整体布局
- 负责当前选中节点状态
- 负责把选中节点传给聊天展示模块
- 负责协调树图模块与聊天模块

不负责：

- 不直接写树图节点映射细节
- 不直接写聊天消息映射细节
- 不直接读数据库原始表

### 2. 树图展示模块

职责：

- 接收树图专用 ViewModel
- 用 `React Flow` 展示节点与边
- 展示当前选中节点高亮状态
- 抛出节点选中事件

不负责：

- 不负责查询数据
- 不负责聊天展示
- 不负责业务操作按钮

### 3. 聊天历史展示模块

职责：

- 接收当前选中节点的聊天线程 ViewModel
- 用 `assistant-ui` 或等价只读线程组件展示消息
- 清晰区分 user / assistant 消息

不负责：

- 不负责节点切换逻辑
- 不负责发送消息
- 不负责 workflow 调用

### 4. 数据查询/适配模块

职责：

- 读取页面所需原始数据
- 生成页面容器、树图模块、聊天模块消费的 ViewModel

不负责：

- 不直接渲染 UI
- 不承担页面交互状态

### 5. 类型与映射模块

职责：

- 定义页面层 ViewModel
- 定义 `SceneNode -> FlowNodeViewModel`
- 定义 `rawMessages -> ChatMessageViewModel`

不负责：

- 不直接访问数据库
- 不直接渲染组件

## 展示行为契约

### 1. 初始加载

- 页面首次加载时，应读取当前树与节点数据。
- 若存在 root 节点，默认选中 root。
- 默认聊天区展示 root 对应的聊天历史。

### 2. 树节点切换

- 用户点击树中的某个节点时，页面更新当前选中节点。
- 右侧聊天区同步切换到该节点对应的聊天历史。
- 切换只影响页面展示，不触发任何持久化写入。

### 3. 聊天区展示

- 聊天区优先展示当前节点的历史消息流。
- 若某节点没有聊天历史，应显示明确的空状态提示，而不是空白区域。
- 消息展示不要求复刻终端格式，但必须保留角色区分与顺序。

### 4. 空状态

- 若当前数据库还没有 root 或没有任何节点，页面应有空状态展示。
- 空状态只用于说明“当前没有可展示内容”，不在页面内引导创建节点操作。

## 数据语义契约

### 1. 树图 ViewModel

树图层至少要能表达：

- 节点 id
- 节点标题或可读标签
- 节点状态
- 父子关系
- 当前是否选中

本里程碑不要求表达复杂样式语义，如拖拽状态、编辑状态、临时占位节点。

### 2. 聊天 ViewModel

聊天展示层至少要能表达：

- 消息唯一标识或稳定顺序标识
- 角色：`user` / `assistant`
- 消息文本内容
- 消息顺序

本里程碑不要求：

- tool 消息展示
- 富文本编辑
- 发送中状态
- typing 状态

### 3. 页面容器 ViewModel

页面容器至少要能表达：

- 当前树是否存在
- 当前选中节点 id
- 树图数据
- 当前选中节点对应的聊天线程

## 失败与边界

### 1. 数据读取失败

- 页面必须显示显式错误状态。
- 不允许静默展示空白页面来掩盖读取失败。

### 2. 节点存在但聊天历史为空

- 视为合法空状态，不视为异常。
- 聊天区应明确提示“当前节点没有聊天历史”。

### 3. 树存在但选中节点无效

- 页面应回退到 root 或其他稳定默认节点。
- 不允许页面停留在无效选中状态导致右侧崩溃。

## 最小验收场景

### 1. 树图展示

- 页面可见当前 root 与 child 关系
- 节点之间关系可视化正确

### 2. 默认选中

- 打开页面后若存在 root，默认显示 root 的聊天历史

### 3. 点击联动

- 点击树中不同节点，右侧聊天区同步切换

### 4. 聊天只读展示

- 聊天区以对话形式展示消息
- 页面中不存在发送消息或确认候选的交互入口

### 5. 空状态

- 无节点时有空状态页面
- 无聊天历史时有空状态聊天区

### 6. 模块化约束

- 页面实现可清晰分辨容器层、树图层、聊天层、适配层、映射层

## 默认假设

- 当前只展示单棵树
- 当前数据库中的 `rawMessages` 足够支持只读聊天展示
- 当前页面层允许通过本地查询层或只读接口层拿数据，但本 spec 不冻结具体传输方式
- 页面视觉风格不是本里程碑重点，优先保证结构清晰、可读、可验收
