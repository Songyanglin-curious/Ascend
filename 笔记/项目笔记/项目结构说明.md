```markdown
# 项目结构说明

## 顶层目录速查

| 目录/文件 | 一句话说明 |
|-----------|-----------|
| `AGENTS.md` | Codex 的长期行为规则，每次启动自动读取 |
| `.codex/config.toml` | Codex 项目级配置（模型、审批策略等） |
| `docs/` | 稳定的设计文档，不随任务变化 |
| `tasks/` | 任务管理，按状态分三档 |
| `packages/` | 后端共享模块，按职责拆分 |
| `apps-api/` | API 服务入口 |
| `apps-web/` | 前端应用入口 |
| `apps-worker/` | 后台任务/异步处理入口 |

---

## docs/ — 设计文档（长期稳定）

改这里的条件：架构变了、模块边界变了、新增核心概念。

### docs/architecture/ — 系统架构设计

| 文件 | 存什么 |
|------|--------|
| `ascend-1.0-design.md` | 产品层面的整体设计（要做什么、核心概念、用户价值） |
| `ascend-1.0-dev-design.md` | 开发层面的技术设计（模块划分、依赖关系、关键接口、数据流） |

判断标准：如果这个信息「换一个任务也要看」，就放这里。

### docs/standards/ — 可复用模板

| 文件 | 存什么 |
|------|--------|
| `spec-template.md` | 新任务写 01-spec 时的格式模板 |
| `plan-template.md` | 新任务写 02-plan 时的格式模板 |
| `checklist-template.md` | 新任务写 checklist 时的格式模板 |
| `review-template.md` | 任务完成后写 05-review 时的格式模板 |

作用：开新任务时复制一份，填内容，不用每次从零想格式。

### docs/decisions/ — 设计决策记录（ADR）

| 文件 | 存什么 |
|------|--------|
| `ADR-xxx.md` | 一次重要的技术选型或架构决策（选了什么、为什么选、放弃了什么、影响范围） |

命名规则：ADR-001、ADR-002 按顺序递增。

---

## tasks/ — 任务管理（按状态流动）

### 流转规则

```

active/  →  done/  →  archive/YYYY-MM/
正在做      刚做完      冷归档

```markdown

- `active/`：当前在做的任务，保持 1~5 个
- `done/`：刚完成，短期内可能回看或修补
- `archive/YYYY-MM/`：已冷却，只留历史记录

### tasks/active/<task-id>/ — 单个任务目录

每个任务一个文件夹，命名格式 `T-001-简短描述`。

| 文件 | 什么时候写 | 什么时候改 | 存什么 |
|------|-----------|-----------|--------|
| `00-task.md` | 任务开始前 | 任务边界变了 | 要解决什么、不解决什么、边界在哪 |
| `01-spec.md` | 明确边界后 | 设计细节变了 | 这次要落实成什么（涉及哪些模块、新增什么接口、哪些不准碰） |
| `02-plan.md` | spec 定稿后 | 执行顺序变了 | 分几步做、每步改哪个文件、每步怎么验证 |
| `checklist.md` | plan 定稿后 | 验收条件变了 | 勾选式验收清单（功能点、测试通过条件、禁止回归项） |
| `05-review.md` | 任务完成后 | 不改 | 实际改了什么、和计划的偏差、遇到的坑、是否需要反写全局文档 |

**核心原则：边界变改 task，设计变改 spec，顺序变改 plan，验收变改 checklist，做完写 review。不串改。**

---

## packages/ — 后端共享模块

按职责拆，控制依赖方向。

| 目录 | 职责 | 可以依赖谁 | 禁止依赖谁 |
|------|------|-----------|-----------|
| `domain/` | 领域模型、业务规则定义 | shared | runtime、persistence、rules |
| `rules/` | 规则引擎、策略执行 | domain、shared | runtime、persistence |
| `runtime/` | 流程编排、任务调度 | domain、rules、shared | persistence（通过接口调用，不直接依赖） |
| `persistence/` | 存储实现、数据访问 | domain、shared | rules、runtime |
| `shared/` | 公共工具类、类型定义、常量 | 无 | 无（最底层） |

依赖方向（只允许箭头方向）：

```

Ascend-* → runtime → rules → domain → shared
              ↘ persistence → domain → shared

```

---

## apps-*/ — 应用入口

| 目录 | 职责 |
|------|------|
| `apps-api/` | 对外提供 API 接口的服务端 |
| `apps-web/` | 前端界面，只发命令和展示，不直接操作层级 |
| `apps-worker/` | 后台异步任务处理 |

共同原则：业务逻辑下沉到 packages/，这里只做组装和接入。

## 根目录文件

| 文件 | 职责 | 谁维护 |
|------|------|--------|
| `AGENTS.md` | Codex 的长期行为规则（仓库结构、命令、依赖方向、禁止事项、完成定义） | 发现可复用的规则时更新，不写当前任务细节 |
| `.codex/config.toml` | Codex 的项目级配置 | 很少改，按需调整 |
```
